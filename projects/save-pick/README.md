# Save Pick

마감이 임박한 신선식품을 할인가로 판매하고, 고객이 원하는 시간에 매장에서 직접 픽업하도록 연결하는 온라인 주문·픽업 서비스입니다.

첫 버전(MVP)은 단일 매장, 매장 픽업 전용 수령, 성공·실패만 판정하는 가상 결제를 전제로 합니다.

## 해결하려는 사용자 문제

| 문제 | 현재 상황 | Save Pick의 해결 |
|---|---|---|
| 매장의 마감 폐기 손실 | 마감 시각까지 팔리지 않은 신선식품은 전량 폐기된다 | 남은 시간에 따라 자동으로 할인해 판매 기회를 늘린다 |
| 할인 정보의 비대칭 | 고객은 매장에 직접 가야 마감 할인 여부를 안다 | 온라인에서 현재 할인가와 잔여 수량을 확인한다 |
| 헛걸음 | 매장 도착 시 이미 품절인 경우가 있다 | 주문 시 재고를 확정해 수령을 보장한다 |
| 픽업 시각 혼잡 | 마감 직전 고객이 몰려 응대가 어렵다 | 픽업 시간대를 나눠 예약받아 분산한다 |

## 서비스 목표

- 폐기 직전 재고를 매출로 전환하고, 마감 할인 대상 상품의 소진율을 높인다.
- 재고 임시 선점으로 "주문했는데 매장에 없는" 상황을 없앤다.
- 픽업 시간대 분산으로 마감 직전 응대 혼잡을 줄인다.

서비스 공개 후 8주를 기준으로 마감 소진율(60% 이상), 픽업 완료율(90% 이상), 노쇼율(5% 이하) 등의 지표로 성과를 측정할 계획입니다. (`docs/01-service-plan.md` §6)

## 주요 사용자

| 구분 | 정의 | 핵심 동기 |
|---|---|---|
| 고객 | 매장을 직접 방문할 수 있는 인근 생활권 소비자 | 신선식품을 정가보다 싸게 사는 것 |
| 관리자 | 매장 운영자 또는 매장 직원 | 폐기 손실을 줄이고 픽업 응대 부담을 예측 가능하게 만드는 것 |

## 핵심 기능 (MVP)

| 영역 | 내용 |
|---|---|
| 계정 | 회원가입, 로그인/로그아웃, 회원 정보 조회·수정 |
| 상품 | 목록, 검색, 정렬·필터, 상세, 마감 할인가·잔여 수량 표시 |
| 구매 | 장바구니, 주문서 생성과 재고 임시 선점(10분), 픽업 날짜·시간대 선택 |
| 결제 | 가상 결제(성공·실패 판정), 실패 시 재시도(최대 3회) |
| 사후 관리 | 주문 내역·상세 조회, 고객 취소, 노쇼 자동 판정과 제재 |
| 운영(관리자) | 상품·재고·주문·픽업 시간대 관리 |

**MVP에서 제외**: 실제 결제 연동, 실시간 배송·라이더 배정, 지도·위치 추적, AI 추천, 다중 매장 재고 연동. (`docs/01-service-plan.md` §5.2)

## 사용자 이용 흐름

```
상품 목록/검색 → 상품 상세(할인가·잔여 수량 확인) → 장바구니
   → 주문서 생성(재고 임시 선점, 10분) → 픽업 날짜·시간대 선택
   → 가상 결제(성공/실패, 실패 시 최대 3회 재시도) → 픽업 번호 발급
   → 매장 픽업 완료 (또는 픽업 시작 1시간 전까지 고객 취소)
```

## 관리자 기능

- 상품 등록·수정, 판매 상태 전환 (재고 미등록 상품은 판매 중으로 전환 불가)
- 재고 조정 (이미 선점·확정된 수량 미만으로는 축소 불가)
- 픽업 번호 기반 주문 조회, 준비 완료·픽업 완료 처리
- 사유를 남기는 관리자 취소
- 영업시간·픽업 정원·시간대 차단 설정

## 사용 기술

### 백엔드 (확정, `docs/14-project-structure.md` §1)

## 주요 설계 및 기술적 고민

- **재고 정합성 이중 방어선**: 애플리케이션 로직(비관적 락 `SELECT ... FOR UPDATE`) 이전에 DB `CHECK` 제약(`total - held - confirmed >= 0`)으로 초과 판매를 물리적으로 차단합니다. (`docs/10-erd.md`, `docs/13-inventory-concurrency.md`)
- **재고 임시 선점과 만료**: 주문서 생성 시 10분간 재고를 선점하고, 결제 미완료 시 자동 만료·복구합니다. 만료 배치와 결제 확정이 동시에 진행되는 경쟁 상황은 조건부 UPDATE로 한쪽만 성공하도록 설계했습니다.
- **멱등성**: 재고 변동 원장(`stock_ledgers`)에 `(order_id, product_id, reason)` 유니크 제약을 걸어, 같은 종결 처리(확정·해제·복구)가 중복 실행되지 않도록 물리적으로 막습니다.
- **도메인 우선 계층 구조**: 폴더를 `controller/service` 같은 기술 계층이 아니라 `account/store/product/stock/cart/pickup/order` 같은 도메인으로 먼저 나누고, 그 안에서 `api/application/domain/infrastructure` 4계층을 반복합니다. 업무 규칙 하나를 고치기 위해 여러 최상위 폴더를 오가지 않도록 하기 위함입니다.
- **시각의 단일 출처**: 모든 시각 판정은 `ServerClock`(주입 가능한 `Clock`)을 거치며, 선점 만료·취소 마감처럼 단일 트랜잭션 안에서 비교하는 판정은 DB의 `now()`를 기준으로 합니다.

## 실행 방법

### 백엔드

```bash
cd backend
docker compose up -d          # 로컬 PostgreSQL 15 기동
./gradlew bootRun             # 앱 기동 시 Flyway 마이그레이션 자동 적용
curl http://localhost:8080/actuator/health
```

### 프론트엔드

```bash
cd frontend
npm install
npm run dev                   # http://localhost:3000
```
