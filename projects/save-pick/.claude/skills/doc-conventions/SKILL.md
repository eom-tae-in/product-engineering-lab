# savePick 문서 공통 규칙

## 파일명

`docs/NN-kebab-case.md` — 번호는 소유 Agent별로 고정한다.

| 번호대 | 소유 |
|---|---|
| 00 | orchestrator (상태) |
| 01~05 | product-planner |
| 06~09 | experience-designer |
| 10~14 | technical-architect |
| 15~17 | quality-reviewer |

## 문서 머리말

모든 문서는 이렇게 시작한다.

```markdown
# 문서 제목

- 문서 ID: 03
- 작성: product-planner
- 최종 갱신: YYYY-MM-DD
- 선행 문서: 01, 02

## 한 줄 요약
이 문서가 무엇을 정의하는지 한 문장.
```

## ID 체계

| 접두사 | 대상 | 예 |
|---|---|---|
| `FR-###` | 기능 요구사항 | FR-014 |
| `BR-###` | 업무 규칙 | BR-007 |
| `SC-###` | 화면 | SC-021 |
| `FL-###` | 사용자 흐름 | FL-003 |
| `API-###` | 엔드포인트 | API-012 |
| `TC-###` | 테스트 케이스 | TC-045 |

ID는 한 번 부여하면 바꾸지 않는다. 삭제할 때는 번호를 재사용하지 말고 `(폐기)`로 표시한다.

## 문체

- 한국어. 간결하고 이해하기 쉽게.
- 서술형(`~한다`)으로 통일한다. `~할 예정`, `~하면 좋겠다` 같은 모호한 표현을 쓰지 않는다.
- 요구사항은 검증 가능해야 한다. "빠르게 로딩된다"가 아니라 "목록 첫 화면이 2초 내에 표시된다".
- 표를 우선 쓴다. 같은 형태의 항목이 3개 이상이면 목록보다 표가 낫다.
- 다이어그램은 Mermaid로 작성한다. 이미지 파일로 만들지 않는다.

## 사용자 제공 내용과 가정의 구분

본문에는 사용자가 제공했거나 확정된 내용만 쓴다.
내가 판단해서 채운 것은 본문에 쓰되 **문서 끝 섹션에 반드시 다시 나열한다.**

## 「가정 / 미확정」 섹션 (모든 문서 필수)

문서 맨 끝에 둔다.

```markdown
---

## 가정 / 미확정

### 가정 (확인 필요)
| # | 가정한 내용 | 근거 | 틀릴 경우 영향 |
|---|---|---|---|
| A1 | 픽업 가능 시간은 매장 영업시간 내로 한정 | 단일 매장 전제 | 시간 선택 화면과 API 전면 수정 |

### 미확정 (결정 대기)
| # | 결정이 필요한 사항 | 선택지 | 막히는 작업 |
|---|---|---|---|
| U1 | 선점 유효 시간 | 5분 / 10분 / 15분 | 동시성 설계, 주문 화면 타이머 |
```

가정이나 미확정이 없으면 `없음`이라고 명시한다. 섹션 자체를 빼지 않는다.

## 범위 규율

MVP 제외 범위: 실제 결제 연동, 실시간 배송·라이더 배정, 지도·위치 추적, AI 추천, 다중 매장 재고 연동.
이 영역의 내용은 본문에 쓰지 않는다. 꼭 남겨야 하면 「가정 / 미확정」에 *향후 검토* 로만 적는다.
