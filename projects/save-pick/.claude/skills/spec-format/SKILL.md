# 요구사항 · 업무 규칙 작성 형식

## 기능 요구사항 항목

```markdown
### FR-014 · 주문 중 재고 임시 선점

- 사용자: 고객
- 관련 규칙: BR-007, BR-008
- 우선순위: 필수 / 선택

**설명**
고객이 주문 화면에 진입하면 선택한 수량만큼 재고를 임시로 선점한다.

**완료 조건**
- [ ] 주문 화면 진입 시 해당 수량이 다른 고객에게 잔여 수량으로 노출되지 않는다
- [ ] 선점 유효 시간이 지나면 재고가 자동으로 복구된다
- [ ] 남은 수량보다 많은 수량은 선점되지 않고 오류로 처리된다

**예외**
- 선점 중 관리자가 재고를 줄여 선점 수량보다 적어진 경우
```

## 완료 조건 작성 규칙

- 관찰 가능한 결과로 쓴다. 내부 구현을 쓰지 않는다.
- 한 조건에 하나의 검증만 담는다.
- 숫자가 필요한 곳에 숫자를 쓴다. 값이 아직 없으면 `[U#]`로 표시하고 「미확정」에 올린다.
- 부정 조건(무엇이 일어나면 안 되는가)을 최소 1개 포함한다.

나쁜 예: `재고가 잘 관리된다`
좋은 예: `동시에 마지막 1개를 주문한 두 고객 중 한 명만 주문에 성공하고, 다른 한 명은 품절 오류를 받는다`

## 업무 규칙 항목

```markdown
### BR-007 · 재고 선점 유효 시간

- 규칙: 선점은 생성 시점부터 [U1]분간 유효하다.
- 적용 대상: 주문 생성 ~ 결제 완료 사이
- 위반 시 처리: 유효 시간 경과 시 선점을 해제하고 재고를 복구한다. 고객에게는 주문 화면에서 만료를 알리고 재확인을 요구한다.
- 근거: 재고 잠금이 무한정 유지되면 다른 고객의 구매가 막힌다.
- 관련 요구사항: FR-014, FR-021
```

## 상태 전이표

상태를 가진 모든 대상(주문, 재고 선점, 결제, 상품)에 대해 작성한다.

```markdown
### 주문 상태

| 현재 상태 | 이벤트 | 다음 상태 | 재고 영향 | 규칙 |
|---|---|---|---|---|
| (없음) | 주문 생성 | PENDING | 선점 +N | BR-007 |
| PENDING | 결제 성공 | CONFIRMED | 선점 → 확정 차감 | BR-009 |
| PENDING | 결제 실패 | FAILED | 선점 해제 +N 복구 | BR-010 |
| PENDING | 선점 만료 | EXPIRED | 선점 해제 +N 복구 | BR-007 |
| CONFIRMED | 고객 취소 | CANCELED | +N 복구 | BR-012 |
| CONFIRMED | 픽업 완료 | COMPLETED | 변화 없음 | |
| CONFIRMED | 픽업 시간 경과 | NO_SHOW | [U#] | BR-013 |
```

같이 적을 것:
- 상태값 이름은 영문 대문자 스네이크로 통일하고, 모든 문서에서 같은 이름을 쓴다
- 표에 없는 전이는 **허용하지 않는다**고 명시한다
- 되돌릴 수 없는 전이를 표시한다

## 고객 / 관리자 분리

두 사용자의 요구사항을 한 절에 섞지 않는다. 문서를 `## 고객`, `## 관리자` 두 절로 나누고, 공통 규칙은 `## 공통`에 둔다.

## 검토 체크

- [ ] 모든 FR에 ID, 사용자 구분, 완료 조건이 있다
- [ ] 완료 조건이 모두 검증 가능하다
- [ ] 상태를 가진 모든 대상에 전이표가 있다
- [ ] 각 BR에 위반 시 처리와 근거가 있다
- [ ] MVP 제외 범위 기능이 없다
