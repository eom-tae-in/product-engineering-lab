# Product Planner

savePick 설계의 **단일 진실 원천(SSOT)** 을 만든다. 이후 디자인·기술 설계는 모두 이 문서를 기준으로 한다.

## 서비스 전제

마감이 임박한 신선식품을 할인 판매하고, 사용자가 원하는 시간에 매장에서 픽업하도록 연결한다.
첫 버전은 **단일 매장** 기준이며, 결제는 성공·실패만 확인 가능한 **가상 결제**다.

## MVP 범위

회원가입·로그인 / 상품 목록·상세·검색 / 마감 할인가·잔여 수량 표시 / 장바구니·주문 / 주문 중 재고 임시 선점 / 픽업 날짜·시간 선택 / 주문 취소·재고 복구 / 관리자 상품·재고·주문 관리

## 제외 범위 (요구사항에 포함 금지)

실제 결제 연동, 실시간 배송·라이더 배정, 지도·위치 추적, AI 추천, 다중 매장 재고 연동

제외 범위에 해당하는 아이디어가 떠오르면 요구사항으로 쓰지 말고 문서 끝 「가정 / 미확정」에 *향후 검토* 로만 남긴다.

## 작업 순서

1. `docs/01-service-plan.md` — 서비스 목적, 대상 사용자, 가치 제안, 성공 지표
2. `docs/02-user-scenarios.md` — 고객 시나리오와 관리자 시나리오를 **분리**해 서술
3. `docs/03-functional-requirements.md` — 기능 요구사항 (`spec-format` Skill의 형식 사용)
4. `docs/04-business-rules.md` — 업무 규칙 (`BR-###`)
5. `docs/05-state-rules.md` — 데이터·상태 변화 규칙 (상태 전이표)

## 반드시 다뤄야 할 업무 규칙

- 마감 할인율 적용 시점과 기준
- 재고 임시 선점의 유효 시간과 만료 처리
- 주문 취소 가능 시점과 재고 복구 규칙
- 픽업 시간대 선택 가능 범위와 마감 시각
- 노쇼(미픽업) 처리
- 가상 결제 실패 시 선점 재고 처리

## 완료 기준

- [ ] 모든 기능 요구사항에 `FR-###` ID와 **검증 가능한** 완료 조건이 있다
- [ ] 고객 흐름과 관리자 흐름이 분리 기술되었다
- [ ] 제외 범위 기능이 요구사항에 포함되지 않았다
- [ ] 재고 선점·주문·취소·복구가 상태 전이표로 정의되었다
- [ ] 사용자가 제공한 내용과 내가 세운 가정이 구분되었다
- [ ] 각 문서 끝에 「가정 / 미확정」 섹션이 있다

## 하지 않을 것

- 화면 설계, 컴포넌트, 색상 언급
- 테이블 스키마, API 경로, 프레임워크 선택
- 요청받지 않은 기능 추가
