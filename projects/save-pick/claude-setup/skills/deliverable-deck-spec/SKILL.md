# 발표 자료 구성 규칙

## 대전제

**내용을 만들지 않는다.** 승인된 문서에 있는 내용만 재구성한다.
슬라이드를 채울 근거가 없으면 채우지 말고, 어떤 문서의 어떤 부분이 비었는지 보고하고 멈춘다.

원문에 없는 것: 시장 규모, 매출 전망, 일정, 팀 구성, 경쟁사 비교, 사용자 수 목표.
이런 슬라이드를 넣고 싶어지면 넣지 않는다.

## 슬라이드 작성 규칙

- 한 장에 핵심 메시지 하나. 제목이 곧 메시지가 되게 쓴다 ("재고 동시성 처리" 대신 "동시 주문에도 재고는 음수가 되지 않는다").
- 장당 불릿 5개 이하, 불릿당 한 줄.
- 문서를 그대로 옮겨 붙이지 않는다. 발표 중 읽히는 분량으로 줄인다.
- 다이어그램과 와이어프레임은 이미지로 넣는다. 텍스트로 다시 설명하지 않는다.
- 발표자 노트에 출처 문서 ID를 적는다.

## PDF 구성 (상세 설계 문서)

승인된 `docs/` 문서를 순서대로 묶는다.

1. 표지 (로고, 문서명, 날짜, 버전)
2. 목차
3. 01~17 순서로 본문
4. 부록 — 화면 목록 전체표, FR↔화면↔API 추적표
5. 부록 — 가정 / 미확정 통합 목록

페이지 번호와 각 장 머리말에 문서 ID를 넣는다.

## 브랜드 적용

`docs/08-brand-guide.md`의 토큰만 사용한다.

- 제목: `--color-brand`
- 본문: `--color-text`
- 강조·할인 관련 수치: `--color-discount`
- 경고·품절 사례: `--color-danger`
- 배경은 흰색 또는 `--color-bg`. 어두운 배경 슬라이드를 섞지 않는다.
- 로고는 `assets/logo/logo-full.svg`, 아이콘 용도는 `logo-symbol.svg`.

가이드에 없는 색을 추가하지 않는다.

## 출처 매핑 (필수 산출물)

`deliverables/source-map.md`에 남긴다.

```markdown
| 슬라이드 | 내용 | 출처 문서 | 출처 위치 |
|---|---|---|---|
| 5 | MVP 범위 | 17-mvp-scope.md | ## 포함 범위 |
```

모든 슬라이드가 이 표에 있어야 한다. 출처를 적을 수 없는 슬라이드는 삭제한다.
