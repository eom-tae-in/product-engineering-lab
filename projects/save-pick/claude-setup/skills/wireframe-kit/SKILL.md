# 와이어프레임 · 프로토타입 제작 규칙

## 기본

- 기준 폭 **360px**. 데스크톱 레이아웃을 먼저 만들지 않는다.
- 결과물은 `wireframes/` 아래 HTML 단일 파일. 외부 CSS/JS 파일로 쪼개지 않는다.
- `docs/08-brand-guide.md`의 컬러·타이포 토큰만 사용한다. 새 색을 즉석에서 만들지 않는다.
- 실제 데이터가 아니라 **대표 사례** 데이터를 쓴다. 가격·수량은 그럴듯한 값으로 채우되 기획 문서의 수치와 모순되지 않게 한다.

## 파일 구성

```
wireframes/
├── index.html              화면 인덱스 (전체 목록 + 링크)
├── customer/               고객 화면
│   ├── sc-001-product-list.html
│   └── ...
└── admin/                  관리자 화면
    └── ...
```

파일명은 `sc-###-화면명.html`. 화면 ID를 파일명에 넣어 `06-screen-list.md`와 대조 가능하게 한다.

## 각 화면 파일에 포함할 것

1. 상단에 화면 ID·이름·사용자·관련 FR을 적은 메타 바 (프로토타입 본체와 시각적으로 구분)
2. 360px 폭의 프레임 안에 실제 화면
3. **상태 전환 토글** — 기본 / 로딩 / 빈 상태 / 오류 / 품절을 버튼으로 전환해 볼 수 있게 한다

상태 전환은 인라인 JS로 클래스만 바꾸는 수준이면 충분하다. 상태를 별도 파일로 나누지 않는다.

## 인덱스 페이지

`index.html`은 모든 화면을 고객/관리자로 나눠 목록화하고, 각 화면으로 링크한다.
화면 옆에 관련 FR ID를 함께 표시해 커버리지를 눈으로 확인할 수 있게 한다.

## 프로토타입 (클릭 가능한 흐름)

주요 흐름 1~2개만 연결한다. 전 화면을 연결하려 하지 않는다.

우선순위:
1. 고객 주문 흐름 — 목록 → 상세 → 장바구니 → 주문 → 픽업 시간 → 결제 → 완료
2. 관리자 주문 처리 흐름 — 주문 목록 → 상세 → 픽업 완료 처리

예외 경로도 최소 하나는 클릭으로 도달할 수 있게 한다 (결제 실패 또는 선점 만료).

## 표현 수준

와이어프레임이므로 다음은 하지 않는다.
- 실제 사진 (회색 박스 + 라벨로 대체)
- 애니메이션, 트랜지션
- 반응형 브레이크포인트 (360px 하나면 된다)
- 실제 API 호출

다음은 반드시 한다.
- 터치 타깃 최소 44×44
- 하단 고정 CTA가 있는 화면은 스크롤 시에도 고정
- 가격·잔여 수량·픽업 시간이 스크롤 없이 보이는지 확인

## 브라우저 저장소 금지

`localStorage`, `sessionStorage`를 쓰지 않는다. 상태는 JS 변수로만 관리한다.

## 검토 체크

- [ ] `06-screen-list.md`의 모든 화면에 대응 파일이 있다
- [ ] 각 파일에 상태 토글이 있고 5개 상태가 동작한다
- [ ] 브랜드 토큰 외의 색상값이 하드코딩되지 않았다
- [ ] index.html에서 모든 화면에 도달할 수 있다
- [ ] 주요 흐름 1개 이상이 클릭으로 끝까지 진행된다
- [ ] 360px에서 가로 스크롤이 발생하지 않는다
