# 검증 · 테스트 형식

## 1. 3방향 추적표

디자인과 기술이 서로를 보지 않고 병렬 작성되므로, 접점은 여기서만 검증된다.

```markdown
| FR | 요구사항 | 화면 | API | 테스트 | 상태 |
|---|---|---|---|---|---|
| FR-014 | 재고 임시 선점 | SC-006 | API-012 | TC-021, TC-022 | OK |
| FR-019 | 노쇼 처리 | — | API-031 | TC-040 | 화면 없음 |
```

`상태` 값은 `OK` / `화면 없음` / `API 없음` / `테스트 없음` / `근거 없음` 중 하나.
`근거 없음` = 요구사항에 없는데 화면이나 API에 존재하는 것 (범위 초과).

표 아래에 요약을 적는다.

```markdown
- 총 요구사항: 42
- 완전 연결: 39
- 미연결: 3 (FR-019, FR-027, FR-033)
- 범위 초과 항목: 1 (SC-018 상품 추천 — MVP 제외 범위)
```

## 2. 접점 정합성 점검

| 점검 항목 | 방법 |
|---|---|
| 화면이 표시하는 모든 데이터가 API 응답에 있는가 | 화면 상세의 "표시 정보" ↔ API 응답 필드 대조 |
| 화면의 오류 상태가 API 오류 코드와 대응하는가 | 화면 오류 상태 ↔ 오류 코드표 대조 |
| 화면의 권한 구분이 권한 매트릭스와 같은가 | 화면 목록의 `사용자` ↔ 권한 매트릭스 대조 |
| 선점 만료 UX가 TTL 설계와 모순되지 않는가 | 주문 화면 타이머 ↔ BR-007, 동시성 문서 대조 |
| 상태값 이름이 모든 문서에서 동일한가 | `05`, ERD 상태 컬럼, API 응답, 화면 표기 대조 |

## 3. 용어 일관성표

```markdown
| 개념 | 발견된 표현 | 위치 | 통일안 |
|---|---|---|---|
| 재고 임시 확보 | 선점 / 홀드 / 예약 | 03, 07, 13 | 선점 |
| 픽업 시각 | 픽업시간 / 수령시간 | 06, 11 | 픽업 시간 |
```

불일치가 없으면 `없음`이라고 쓴다.

## 4. 문서 판정 (발행 단계가 읽는 표)

```markdown
## 문서 판정

| 문서 | 소유 Agent | 판정 | 사유 |
|---|---|---|---|
| 03-functional-requirements.md | product-planner | 승인 | |
| 06-screen-list.md | experience-designer | 수정필요 | FR-019 대응 화면 없음 |
```

- 판정은 `승인` 또는 `수정필요` 둘 중 하나만 쓴다. 다른 표현을 쓰지 않는다.
- `수정필요`에는 구체적 사유와 소유 Agent를 반드시 적는다.
- 문서를 직접 고치지 않는다. 지적하고 소유 Agent에게 넘긴다.

## 5. 테스트 케이스 형식

```markdown
### TC-021 · 선점 유효 시간 만료 시 재고 복구

- 관련: FR-014, BR-007, API-012
- 유형: 정상 / 예외 / 동시성 / 권한
- 사용자: 고객

**사전 조건**
상품 A의 잔여 수량 5. 고객이 2개로 주문을 생성해 PENDING 상태.

**절차**
1. 결제하지 않고 선점 유효 시간이 지날 때까지 대기한다.
2. 다른 고객이 상품 A 상세를 조회한다.

**기대 결과**
- 주문 상태가 EXPIRED로 바뀐다
- 상품 A의 가용 수량이 5로 복구된다
- 원래 고객의 주문 화면에 만료 안내가 표시된다
```

## 반드시 포함할 테스트 케이스

| 영역 | 최소 케이스 |
|---|---|
| 동시성 | 마지막 1개 동시 주문, 선점 중 관리자 재고 축소 |
| 선점 | TTL 만료 복구, 결제 실패 시 해제 |
| 취소 | 취소 후 재고 복구, 취소 요청 중복 호출(멱등성) |
| 픽업 | 마감된 시간대 선택 시도, 영업시간 외 선택 |
| 결제 | 가상 결제 성공, 실패 |
| 권한 | 비로그인 주문 시도, 고객의 관리자 API 접근 |
| 재고 | 잔여 0 상품 주문 시도, 잔여보다 많은 수량 요청 |

## 6. MVP 완료 기준

`17-mvp-scope.md`에 검증 가능한 문장으로 쓴다.

```markdown
| # | 완료 기준 | 검증 방법 |
|---|---|---|
| 1 | 고객이 로그인 후 상품 선택부터 가상 결제 완료까지 중단 없이 진행할 수 있다 | TC-001~TC-010 |
| 2 | 동시 주문 시 재고가 음수가 되지 않는다 | TC-021, TC-022 |
```

"잘 동작한다" 같은 문장을 쓰지 않는다.
