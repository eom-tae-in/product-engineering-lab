## 한 줄 요약
savePick 첫 버전에 필요한 고객 화면 15개와 관리자 화면 13개를 진입·이탈 경로, 표시 정보, 화면 상태(빈·로딩·오류 포함), 권한과 함께 정의하고 모든 기능 요구사항을 화면에 매핑한다.

## 0. 읽는 방법

- 기준 폭은 **360px**이며 모든 화면은 모바일 세로 화면을 먼저 설계한다.
- 화면 ID는 고객 `SC-001~SC-015`, 관리자 `SC-101~SC-113`으로 구분한다. 한 번 부여한 ID는 바꾸지 않는다.
- `사용자` 값은 `고객`, `관리자`, `비로그인` 조합으로만 쓴다.
- 모든 화면은 **기본 / 로딩 / 빈 상태 / 오류** 4종을 정의한다. 해당 없는 경우에도 `해당 없음`과 그 사유를 적는다.
- 화면에 표시하는 시간·할인율·정원 수치는 `04-business-rules.md`의 확정값을 그대로 쓴다.
- 상태값 이름은 `05-state-rules.md`의 영문 대문자 스네이크 표기를 그대로 쓴다.

## 3. 고객 화면 상세

### SC-001 · 홈 · 상품 목록

- 사용자: 비로그인, 고객
- 권한: 로그인 없이 전체 조회 가능. 주문 관련 액션은 SC-012로 유도한다 (FR-004)
- 진입: 서비스 진입 / SC-002 검색 취소 / SC-008 계속 보기 / 하단 탭 `홈`
- 이탈: SC-002(검색), SC-003(상품 상세), SC-004(장바구니 탭), SC-009(주문 내역 탭), SC-014(마이페이지 탭)

**표시 정보 (카드 1장 기준 6개 정보)**

| 항목 | 규칙 |
|---|---|
| 상품명 | 1행, 넘치면 말줄임 |
| 정가 | 취소선, 보조색 |
| 현재 할인가 | 카드에서 가장 큰 글자 |
| 할인율 배지 | `30% 할인` 형태. 붉은 배지를 쓰지 않는다 |
| 절약 금액 | `4,100원 아낌` |
| 잔여 수량 | `남은 수량 8개`. 5개 이하이면 `소진 임박` 문구를 함께 표시한다 (FR-015) |
| 마감 시각 | `오늘 21:00 마감` |

**주요 액션**
- 상품 카드 탭 → SC-003
- 검색창 탭 → SC-002
- 정렬 변경: 마감 임박 순(기본) / 할인율 높은 순 / 가격 낮은 순 (FR-012)
- 품절 숨기기 토글 (FR-012)

**상태**

| 상태 | 표시 |
|---|---|
| 기본 | 마감 임박 순 상품 카드 목록. 상단에 매장명과 영업시간 10:00~22:00 |
| 로딩 | 카드 스켈레톤 4장. 정렬 바는 비활성 |
| 빈 상태 | `지금 판매 중인 상품이 없어요` + `매장 영업시간은 10:00~22:00입니다` + 새로고침 버튼 |
| 재고 소진 | 카드 전체 60% 불투명 + `품절` 배지. 탭은 되지만 상세에서 담기 불가. 정렬 결과에서 항상 목록 끝으로 밀린다 |
| 마감 도달 | 마감 시각이 지난 상품(CLOSED)은 목록에서 즉시 빠진다 (FR-034). 목록이 갱신되면 `상품 2건이 마감돼 목록에서 빠졌어요` 안내 줄을 1회 노출한다 (**안내 줄만 미구현** — 아래 참고) |
| 오류 | `상품을 불러오지 못했어요` + `다시 시도` 버튼. 이전 목록은 지우지 않는다 |
| 주문 제한 계정 | 상단에 `노쇼 3회로 2026-09-04 19:00까지 새 주문을 만들 수 없어요` 배너. 조회와 담기는 그대로 가능 (FR-032) |

> **구현 메모(2026-09-03)**: 「마감 도달」의 두 문장 중 **앞 문장(목록에서 즉시 제외)은 구현했다** — 조회 API가 배치를 기다리지 않고 마감 상품을 걸러낸다(11번 §11 BATCH-02 보완, FR-014·FR-034). 회귀 테스트는 TC-070이다.
>
> 뒤 문장의 **`상품 N건이 마감돼 목록에서 빠졌어요` 안내 줄은 구현하지 않았다.** "빠졌다"를 알려면 직전 조회 결과와 지금 결과를 비교해야 하는데, 이 화면은 서버 렌더 + 사용자 새로고침 방식이라 "직전에 무엇을 보고 있었는지"를 알지 못한다. 안내 줄 하나를 위해 목록 폴링(주기적 재조회)을 도입하면 요청량·배터리 비용과 다른 화면과의 갱신 정책 불일치가 따라온다 — 안내가 없어도 마감 상품은 이미 목록에서 사라져 사용자가 잘못된 상품을 담을 수는 없으므로, 비용 대비 이득이 낮다고 판단해 첫 버전에서 제외한다.
>
> 되살리려면 목록 갱신 주기를 먼저 정해야 한다(FR-014의 "60초 안에 반영"과 맞물린다). 주기가 정해지면 이전 응답과의 차집합으로 안내 줄을 만든다.

**모바일 배치**
- 스크롤 없이 보여야 하는 것: 검색창, 정렬 바, 첫 카드의 할인가·잔여 수량
- 하단 고정 액션 바: 없음. 대신 하단 고정 탭 바(홈 / 장바구니 / 주문 내역 / 마이페이지)

### SC-002 · 상품 검색

- 사용자: 비로그인, 고객
- 권한: 제한 없음
- 진입: SC-001 검색창 탭
- 이탈: SC-003(결과 선택), SC-001(검색 취소)

**표시 정보**
- 검색 입력창, 검색 결과 카드(SC-001과 동일한 카드 구성)

**주요 액션**
- 검색어 입력·삭제, 결과 카드 탭, 취소

**상태**

| 상태 | 표시 |
|---|---|
| 기본 | 결과 카드 목록과 `"삼겹살" 검색 결과 4건` |
| 로딩 | 카드 스켈레톤 3장 |
| 빈 상태(검색 전) | `상품명으로 찾아보세요` 안내 문구만 표시 |
| 빈 상태(결과 없음) | `"OO"와 일치하는 판매 중 상품이 없어요` + `전체 상품 보기` 버튼 |
| 재고 소진 | SC-001과 동일하게 `품절` 배지 처리 |
| 오류 | `검색에 실패했어요` + `다시 시도` |

**규칙 반영**
- 검색어가 비면 전체 목록과 같은 결과를 보여준다 (FR-011)
- HIDDEN, CLOSED, DRAFT 상품은 정확한 이름으로 검색해도 결과에 넣지 않는다

### SC-003 · 상품 상세

- 사용자: 비로그인, 고객
- 권한: 조회는 제한 없음. 담기도 로그인 없이 가능하다 (미로그인 장바구니 유지)
- 진입: SC-001·SC-002 카드 탭 / SC-004 품목명 탭
- 이탈: SC-004(담기 후 장바구니 보기), 뒤로(SC-001·SC-002)

**표시 정보 (9개)**
상품명, 설명, 판매 단위, 정가(취소선), 현재 할인가, 할인율·절약 금액, 잔여 수량, 마감 시각, 1회 주문 최대 수량

**주요 액션**
- 수량 조절(1 ~ 1회 주문 최대 수량, 기본 최대 5)
- 장바구니 담기 → 하단 시트로 `담았어요` + `장바구니 보기`

**상태**

| 상태 | 표시 |
|---|---|
| 기본 | 이미지 자리(회색 박스) + 정보 + 하단 고정 담기 바 |
| 로딩 | 이미지·텍스트 스켈레톤. 하단 담기 바는 비활성 |
| 빈 상태 | 해당 없음. 단일 대상 화면이므로 빈 목록 개념이 없다 |
| 재고 소진 | 가격 정보는 그대로 두고 잔여 수량 자리에 `품절`. 수량 조절기와 담기 버튼 비활성. 하단 바 문구 `지금은 담을 수 없어요` |
| 마감 도달 | 상단에 `판매가 종료된 상품이에요 (21:00 마감)` 안내 띠. 담기 버튼 비활성 (FR-034) |
| 수량 초과 | 최대 수량에 도달하면 `+` 비활성 + `1회 최대 5개까지 담을 수 있어요` 캡션 |
| 오류(품목 수 초과) | 담기 시도 시 하단 시트 `장바구니에는 품목을 10개까지 담을 수 있어요. 정리한 뒤 다시 담아주세요` + `장바구니로 이동`. 담기를 진행하지 않는다 (BR-009, `CART_ITEM_LIMIT_EXCEEDED`) |
| 오류(없는 상품) | `상품을 찾을 수 없어요` 전체 화면 + `상품 목록으로` 버튼 |
| 오류(통신) | `정보를 불러오지 못했어요` + `다시 시도` |

**모바일 배치**
- 스크롤 없이: 상품명, 할인가, 할인율, 잔여 수량, 마감 시각
- 하단 고정 액션 바: 사용. 수량 조절기 + `장바구니 담기`

### SC-004 · 장바구니

- 사용자: 비로그인, 고객
- 권한: 담기·수정은 비로그인 가능. `주문하기`는 로그인 필요 → SC-012 (FR-004)
- 진입: 하단 탭 `장바구니` / SC-003 담기 후 / SC-005·SC-006·SC-007 선점 만료 복귀 / SC-012 로그인 성공 후 복귀
- 이탈: SC-003(품목명 탭), SC-005(주문하기 성공), SC-012(미로그인 주문 시도)

**표시 정보**
- 품목별: 상품명, 현재 할인가, 수량 조절기, 품목 합계
- 하단 요약: 정가 합계, 할인 합계, 결제 예정 금액

**주요 액션**
- 수량 변경(0으로 내리면 삭제), 품목 삭제, 구매 불가 품목 일괄 삭제, 주문하기

**상태**

| 상태 | 표시 |
|---|---|
| 기본 | 품목 목록 + 금액 요약 + 하단 고정 `주문하기` |
| 로딩 | 품목 행 스켈레톤 2개. 주문하기 비활성 |
| 빈 상태 | `장바구니가 비어 있어요` + `마감 할인 상품 보러 가기` 버튼 |
| 재고 소진 | 해당 행에 `품절` 배지, 수량 조절기 비활성, 행 배경 경고색 약하게. 상단에 `구매할 수 없는 품목 1건이 있어요` 안내 + `구매 불가 품목 삭제` 버튼 |
| 재고 부족 | 행에 `남은 수량 1개 · 2개 부족` 표시. 수량을 잔여 수량까지 자동 제안하되 임의로 바꾸지 않는다 (FR-018) |
| 가격 변동 | 행에 `할인 구간이 바뀌어 가격이 8,400원 → 6,000원으로 변경됐어요` 캡션 (FR-018) |
| 마감 도달 | 행에 `판매 종료` 배지. 구매 불가 품목으로 분류한다 (FR-034) |
| 품목 10개 도달 | 상단 안내 `장바구니에 품목을 10개까지 담았어요. 새 품목을 담으려면 먼저 정리해주세요`. 이 상태에서 SC-003에서 새 품목을 담으려 하면 `CART_ITEM_LIMIT_EXCEEDED` 오류로 막힌다 (BR-009) |
| 구매 불가 존재 | `주문하기` 비활성 + 버튼 위 문구 `구매할 수 없는 품목을 정리하면 주문할 수 있어요` |
| 오류(주문서 생성 실패 · 품절) | 하단 시트 `방금 다른 고객이 먼저 담았어요` + 부족 품목·수량 목록 + `장바구니 새로고침`. 부분 선점은 만들지 않는다 (BR-027) |
| 오류(주문서 생성 실패 · 시스템 오류) | 하단 시트 `일시적인 오류로 주문서를 만들지 못했어요. 잠시 뒤 다시 시도해주세요` + `다시 시도`. 재고 행 락 대기가 3초를 넘는 등 시스템 오류(`INTERNAL_ERROR`, 500)이며 트랜잭션 전체가 롤백돼 재고·주문 상태는 바뀌지 않는다. 화면은 SC-004에 그대로 머무른다 (13번 §3) |
| 오류(주문 제한) | 하단 시트 `노쇼 3회 누적으로 2026-09-04 19:00까지 주문할 수 없어요` (FR-032) |
| 오류(진행 중 주문서 존재) | 하단 시트 `진행 중인 주문서가 있어요` + `주문서로 이동` (FR-019) |
| 오류(통신) | `장바구니를 불러오지 못했어요` + `다시 시도` |

**모바일 배치**
- 스크롤 없이: 첫 품목의 가격·수량, 결제 예정 금액 요약 일부
- 하단 고정 액션 바: 사용. `결제 예정 금액` + `주문하기`

### SC-005 · 주문서 작성

- 사용자: 고객
- 권한: 로그인 필수. 주문 제한 계정(RESTRICTED)은 진입할 수 없다
- 진입: SC-004 `주문하기` 성공 (주문 PENDING 생성 + 재고 선점 시작)
- 이탈: SC-006(다음 단계), SC-004(주문서 포기·선점 만료)

**표시 정보**
- 상단 고정 선점 타이머 `09:58` (초 단위, 서버 시각 기준 · FR-005)
- 품목별 확정 단가·수량·합계, 결제 확정 금액
- 픽업 연락처(이름·휴대폰 번호)
- 안내: `주문서 금액은 지금 시점의 할인가로 고정돼요` (FR-021)

**주요 액션**
- `픽업 시간 고르기` → SC-006
- `주문서 포기` → 선점 해제, 주문 EXPIRED, SC-004 복귀

**상태**

| 상태 | 표시 |
|---|---|
| 기본 | 타이머(브랜드색) + 품목 + 확정 금액 + 하단 고정 CTA |
| 로딩 | 주문서 생성 중 전체 화면 로더 `재고를 확보하는 중이에요`. 이 화면에서 이탈 버튼을 노출하지 않는다 |
| 오류(생성 실패 · 시스템 오류) | 로딩 중 재고 행 락 대기 3초 초과 등 시스템 오류(`INTERNAL_ERROR`, 500)가 발생하면 이 화면 대신 SC-004로 돌아가 하단 시트로 안내한다 (문구는 SC-004 `오류(주문서 생성 실패 · 시스템 오류)` 참조). 재고·주문 상태는 바뀌지 않는다 (13번 §3) |
| 빈 상태 | 해당 없음. 품목이 없으면 주문서 자체가 만들어지지 않는다 |
| 만료 임박 | 남은 시간 1분 이하가 되면 타이머가 경고색으로 바뀌고 `1분 뒤 선점이 풀려요. 시간은 연장되지 않아요` 배너 표시 (FR-020) |
| 선점 만료 | 화면을 덮는 시트 `선점 시간이 끝났어요` + `선점한 수량은 다른 고객이 살 수 있게 돌아갔어요` + `장바구니에서 다시 주문하기`. 뒤로가기로 주문서에 되돌아갈 수 없다 (EXPIRED → PENDING 불가) |
| 재고 소진 | 이 화면에서는 발생하지 않는다. 선점이 이미 성립했기 때문이며, 실패는 SC-004 단계에서 처리한다 |
| 오류(통신) | 하단 시트 `주문서를 불러오지 못했어요` + `다시 시도`. 타이머는 서버 응답 값으로 다시 맞춘다 |

**모바일 배치**
- 스크롤 없이: 선점 타이머, 결제 확정 금액
- 상단 고정: 타이머 바 / 하단 고정 액션 바: `픽업 시간 고르기`

### SC-006 · 픽업 날짜·시간대 선택

- 사용자: 고객

- 진입: SC-005 `픽업 시간 고르기`

**표시 정보**

- 선택한 시간대 요약과 취소 가능 마감 시각 미리 보기

**시간대 칩 상태 (6종)**

| 칩 상태 | 표시 | 근거 |
|---|---|---|
| 선택 가능 | 흰 배경 + 테두리, `20:00~20:30` 아래 `4/20` | BR-016 |
| 선택됨 | 브랜드색 채움 | — |

| 운영 차단 | 흐림 + `운영 중단`. 관리자가 닫은 시간대 | FR-058 |

**상태**

| 상태 | 표시 |
|---|---|
| 기본 | 날짜 2개 + 시간대 칩 그리드(3열) |
| 로딩 | 칩 스켈레톤 12개 |
| 빈 상태(오늘 전부 불가) | 오늘 탭에 `오늘은 선택할 수 있는 시간대가 없어요` + 자동으로 내일 탭 선택 (FR-022) |
| 빈 상태(양일 전부 불가) | 전체 안내 `지금은 예약할 수 있는 픽업 시간대가 없어요` + 사유 구분 표시(정원 초과 / 상품 마감 시각 초과 / 영업 종료) + `주문서 포기하고 장바구니로` (FR-023) |

| 오류(선택 직후 정원 소진) | 칩을 즉시 `정원 20/20`으로 갱신하고 하단 시트 `방금 정원이 찼어요. 다른 시간대를 골라주세요` |

- 하단 고정 액션 바: 선택한 시간대 + `결제하기`. 미선택 시 비활성 (FR-023)

### SC-007 · 결제 확인 및 결과

- 사용자: 고객
- 권한: 로그인 필수. PENDING 주문서 + 시간대 선택 완료 상태에서만 진입한다
- 진입: SC-006 `결제하기`
- 이탈: SC-008(성공), SC-006(시간대 다시 선택), SC-004(3회 실패·선점 만료)

**표시 정보**
- 선점 타이머, 픽업 날짜·시간대, 품목 요약, 결제 확정 금액
- 안내: `가상 결제입니다. 실제 금전 거래는 일어나지 않아요`
- 재시도 시: 남은 재시도 횟수와 남은 선점 시간 (FR-025)

**주요 액션**
- `결제하기` 실행, 실패 시 `다시 결제하기`, `시간대 다시 고르기`, `주문서 포기`

**상태**

| 상태 | 표시 |
|---|---|
| 기본 | 결제 요약 + 하단 고정 `12,300원 결제하기` |
| 로딩 | 버튼 자리에 진행 표시 + `결제 결과를 확인하는 중이에요`. 이 동안 버튼 재탭을 막는다 (중복 성공 방지) |
| 빈 상태 | 해당 없음 |
| 결제 실패(1회) | 시트 `결제가 완료되지 않았어요` + `선점은 08:12 남았고, 2번 더 시도할 수 있어요` + `다시 결제하기` (FR-025) |
| 결제 실패(2회) | 같은 시트에 `1번 더 시도할 수 있어요`. 남은 횟수를 경고색으로 표시 |
| 결제 실패(3회·최종) | 전체 화면 `주문이 종료됐어요` + `선점한 수량은 다시 판매 가능해졌어요` + `장바구니에서 다시 주문하기`. 이 주문서로는 재결제할 수 없다 (BR-012) |
| 선점 만료 | SC-005와 동일한 만료 시트. 재시도 횟수가 남아 있어도 결제를 진행하지 않는다 |
| 오류(금액 불일치) | 시트 `주문 금액이 달라졌어요. 주문서를 다시 확인해주세요` + `주문서로 이동`. 결제를 진행하지 않는다 (BR-029) |
| 오류(결제 직전 예약 마감) | 시트 `선택한 시간대의 예약이 방금 마감됐어요` + `다른 시간대 고르기` → SC-006. 결제를 진행하지 않고 재시도 횟수를 차감하지 않는다 (BR-015, `SLOT_CLOSED`) |
| 오류(시간대 정원 소진) | 시트 `선택한 시간대의 정원이 찼어요` + `다른 시간대 고르기` → SC-006 (BR-016) |
| 오류(통신·무응답) | 실패와 동일하게 처리하고 재시도 횟수 1회를 차감한다. 시트에 `응답을 받지 못해 실패로 처리했어요`를 함께 표시 (BR-011) |
| 오류(시스템 오류) | 시트 `일시적인 오류로 결제를 처리하지 못했어요. 잠시 뒤 다시 시도해주세요` + `다시 시도`. 재고 행 락 대기가 3초를 넘는 등 시스템 오류(`INTERNAL_ERROR`, 500)로, 결제 시도 자체가 기록되지 않아 재시도 횟수를 차감하지 않는다 (13번 §4) |

**모바일 배치**
- 스크롤 없이: 픽업 시간대, 결제 확정 금액, 선점 타이머
- 하단 고정 액션 바: 사용

**주요 액션**

**상태**

| 빈 상태(전체) | `아직 주문이 없어요` + `마감 할인 상품 보러 가기` |
| 빈 상태(필터) | `"취소"에 해당하는 주문이 없어요` + `전체 보기` |

### SC-010 · 주문 상세

- 사용자: 고객
- 권한: 로그인 필수. 본인 주문이 아니면 조회되지 않는다 (FR-028)
- 진입: SC-009 주문 선택 / SC-008 주문 상세 보기

- 취소 가능 여부와 취소 가능 마감 시각
- 상태 변경 이력(확정 / 준비 완료 / 완료 / 취소 / 노쇼)과 각 시각
- 관리자 취소 건은 취소 사유

**상태**

| 상태 | 표시 |
|---|---|
| 기본(CONFIRMED) | 픽업 번호 강조 + 하단 고정 `주문 취소하기` |
| 기본(READY) | `매장에서 준비를 마쳤어요` 안내 띠 추가 |
| 로딩 | 카드 전체 스켈레톤 |
| 빈 상태 | 해당 없음 |
| 취소 불가(마감 경과) | 취소 버튼 비활성 + `19:00에 취소 가능 시각이 지났어요. 매장으로 문의해주세요` (FR-030) |
| 취소 불가(COMPLETED) | 취소 버튼 숨김 + `20:12에 픽업이 완료된 주문이에요` |
| 취소 불가(CANCELED) | `2026-08-28 18:34에 취소된 주문이에요` + 취소 주체와 사유 |
| 노쇼 | 상단에 `21:00에 노쇼로 처리됐어요` + `결제 금액은 환불되지 않아요` + `최근 30일 노쇼 2회` (FR-031) |
| 결제 실패(FAILED) | `결제가 3회 실패해 종료된 주문이에요. 픽업 번호는 발급되지 않았어요` |
| 오류(권한) | `조회할 수 없는 주문이에요` + `주문 내역으로` |
| 오류(통신) | `주문 정보를 불러오지 못했어요` + `다시 시도` |

### SC-011 · 주문 취소 확인

- 사용자: 고객
- 권한: 로그인 필수. CONFIRMED·READY이고 취소 마감 전인 본인 주문만
- 진입: SC-010 `주문 취소하기`
- 이탈: SC-010(취소 완료·취소 중단)

**표시 정보**
- 취소 대상 주문 요약(픽업 번호, 픽업 시간대, 결제 금액)
- 경고: `부분 취소는 할 수 없어요. 주문 전체가 취소돼요` (BR-024)
- 안내: `취소한 수량은 바로 다시 판매돼요` / 상품 마감 이후이면 `마감 시각이 지나 재고로 되돌리지 않아요` (BR-019)

**상태**

| 상태 | 표시 |
|---|---|
| 기본 | 확인 시트 + `취소하지 않기` / `전체 취소하기` |
| 로딩 | `취소 처리 중이에요`. 버튼 비활성 |
| 빈 상태 | 해당 없음 |
| 오류(마감 경과) | `방금 취소 가능 시각이 지났어요 (19:00)` + `닫기`. 취소를 실행하지 않는다 |
| 오류(상태 불일치 · `CANCEL_NOT_ALLOWED`) | 이미 취소할 수 없는 상태(COMPLETED·NO_SHOW·CANCELED)로 바뀐 뒤 취소를 시도한 경우다. 서버가 돌려준 실제 현재 상태에 따라 아래 표대로 문구를 분기하고, 공통으로 `주문 상세로` 버튼을 둔다 |
| 오류(통신) | `취소하지 못했어요` + `다시 시도` |

**오류(상태 불일치) 문구 분기**

같은 취소 요청이 느린 응답 때문에 재전송되는 경우(예: 방금 취소에 성공한 직후 재시도)도 이 표로 처리한다. 실제 현재 상태를 기준으로 분기하므로, 이미 취소에 성공한 주문에 "픽업 완료"처럼 사실과 다른 문구를 보여주지 않는다.

| 실제 현재 상태 | 문구 |
|---|---|
| COMPLETED | `이미 처리된 주문이에요. 현재 상태는 픽업 완료예요` |
| CANCELED | `이미 취소된 주문이에요` (취소 요청 재전송 포함) |
| NO_SHOW | `이미 노쇼로 처리된 주문이에요` |

## 4. 관리자 화면 상세

관리자 화면 전체에 공통으로 적용한다.

| 항목 | 규칙 |
|---|---|
| 권한 | 관리자 권한 계정만 접근한다. 고객 권한 계정이 접근하면 `접근 권한이 없어요` 전체 화면을 보여주고 어떤 데이터도 표시하지 않는다 (FR-004) |
| 미인증 | SC-101로 보낸다 |
| 진입 경로 | 고객 서비스와 분리된 관리자 전용 진입 주소를 쓴다 |
| 공통 오류 | `불러오지 못했어요` + `다시 시도`. 직전 데이터는 지우지 않는다 |

### SC-101 · 관리자 로그인

- 사용자: 비로그인
- 진입: 관리자 전용 진입 주소
- 이탈: SC-102(성공)

**표시 정보**: 이메일, 비밀번호, `관리자 로그인`, 안내 `관리자 계정은 운영자가 직접 부여해요` (FR-004)

| 상태 | 표시 |
|---|---|
| 기본 | 입력 폼 |
| 로딩 | 버튼 진행 표시 |
| 빈 상태 | 해당 없음 |
| 오류(인증 실패) | `이메일 또는 비밀번호를 확인해주세요` |
| 오류(권한 없음) | 고객 계정으로 로그인 성공해도 `관리자 권한이 없는 계정이에요`를 보여주고 관리자 화면을 열지 않는다 |
| 오류(잠금) | `로그인 시도가 많아 10분간 잠겼어요` |

### SC-102 · 관리자 홈

- 사용자: 관리자
- 진입: SC-101 로그인 성공 / 각 관리 화면 뒤로
- 이탈: SC-103·SC-105·SC-107·SC-108·SC-109·SC-111·SC-112·SC-113

**표시 정보**
- 오늘 요약: 확정 주문 건수, 준비 완료 건수, 픽업 완료 건수, 노쇼 건수, 판매 가능 0인 상품 수
- 다음 픽업 시간대와 그 시간대 예약 건수
- 픽업 번호 빠른 입력창
- 메뉴 8개: 상품 관리 / 재고 관리 / 재고 이력 / 할인 정책 / 주문 관리 / 픽업 현황 / 노쇼 / 운영 설정

> **구현 메모(2026-09-03)**: 「재고 이력」은 이 문서 안에서도 어긋난다 — 위 메뉴에는 있지만 같은 절의 「이탈」 목록에는 SC-106이 없고, SC-106 자신도 진입 경로를 "SC-105 `이력 보기`"로만 정의한다. 이력은 상품별 조회(API-111)라 상품을 고르지 않고 여는 화면이 없어, 이 메뉴는 이력으로 갈 수 있는 실제 진입점인 재고 관리(SC-105)로 연결했다. 상품 무관 통합 이력 화면이 필요해지면 SC-106의 진입 경로와 API-111의 조회 단위를 함께 정해야 한다.

| 상태 | 표시 |
|---|---|
| 기본 | 요약 카드 + 빠른 입력 + 메뉴 목록 |
| 로딩 | 요약 카드 스켈레톤 4개 |
| 빈 상태 | 오늘 주문이 없으면 `오늘 들어온 주문이 없어요` |
| 오류 | 요약 카드 자리에 `요약을 불러오지 못했어요` + `다시 시도`. 메뉴는 계속 쓸 수 있게 둔다 |

### SC-103 · 상품 관리 목록

- 사용자: 관리자
- 진입: SC-102 `상품 관리`
- 이탈: SC-104(선택·등록), SC-105(재고 보기), SC-107(할인 정책)

**표시 정보**
- 상품별: 상품명, 상태 배지(DRAFT / ON_SALE / HIDDEN / CLOSED), 정가, 현재 적용 할인율, 현재 할인가, 판매 가능 수량, 마감 시각

**주요 액션**
- 상태 필터, 상품 탭 → SC-104, 상태 전환(ON_SALE ↔ HIDDEN, DRAFT → ON_SALE), `상품 등록`

| 상태 | 표시 |
|---|---|
| 기본 | 상품 행 목록 + 상태 필터 |

### SC-112 · 노쇼 목록

- 사용자: 관리자
- 진입: SC-102 `노쇼` / SC-108 상태 필터 `노쇼`
- 이탈: SC-110(주문 선택)

**표시 정보**
- 노쇼 주문: 주문 번호, 픽업 번호, 픽업 시간대, 노쇼 판정 시각, 결제 금액
- 노쇼 전환 예정 목록: 유예가 남은 CONFIRMED·READY 주문과 전환 예정 시각. 남은 유예가 15분 이하이면 전환 예정 시각 옆에 `유예 NN분 남음` 배지(경고색)를 추가로 표시한다 (아래 배지 규칙)
- 안내: `노쇼는 픽업 종료 30분 뒤 자동으로 전환돼요. 재고는 복구되지 않아요` (FR-053)

**전환 예정 배지 규칙**

| 남은 유예 시간 | 표시 |
|---|---|
| 15분 초과 | 전환 예정 시각만 표시 (`전환 예정 20:00`) |
| 15분 이하 | 전환 예정 시각 + `유예 12분 남음` 배지(경고색) |

이 배지는 분 단위이며 목록을 다시 불러올 때 다시 계산한다. 초 단위로 매초 갱신하지 않는다 — 초 단위 실시간 카운트다운은 08-brand-guide.md §2.3 규칙에 따라 선점 타이머(SC-005·SC-006·SC-007)에만 쓴다.

| 상태 | 표시 |
|---|---|
| 기본 | `노쇼` / `전환 예정` 2개 탭 |
| 로딩 | 행 스켈레톤 4개 |
| 빈 상태 | `오늘 노쇼로 처리된 주문이 없어요` |
| 오류(중복 처리) | 이미 NO_SHOW인 주문에 대해 수동 처리를 시도하면 `이미 21:00에 노쇼로 전환된 주문이에요`를 알리고 이력을 추가로 만들지 않는다 (**미구현** — 아래 참고) |
| 오류(통신) | 공통 오류 |

> **구현 메모(2026-09-03)**: 위 「오류(중복 처리)」는 관리자가 노쇼를 **수동으로** 처리하는 경로를 전제하지만, `11-api-spec.md` 가정 A-A7이 "관리자 수동 노쇼 처리 API를 만들지 않는다(자동 전환이 정본)"로 확정해 해당 API가 없다. 이 화면에도 수동 처리 버튼을 두지 않았고, 따라서 이 오류 상태는 발생할 수 없어 구현하지 않았다. A-A7이 뒤집혀 `POST /api/admin/orders/{id}/no-show`가 추가되면 이 행과 함께 되살린다.
