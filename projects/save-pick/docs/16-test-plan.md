## 0. 읽는 방법

- TC ID는 `TC-###` 형식이며 한 번 부여하면 바꾸지 않는다.
- `유형`은 `정상 / 예외 / 동시성 / 권한` 중 하나 이상을 쓴다.
- 각 TC는 최소 1개의 `FR-###`를 `관련`에 포함한다. 필요하면 `BR-###`, `API-###`, `SC-###`를 함께 적는다.
- 그룹 A~K는 FR 커버리지, 그룹 L~N은 `15-review-report.md`가 요구하는 동시성·권한·접점 교차 검증을 담당한다.

- 관련: 12번 §3.3
- 유형: 권한
- 절차: 다른 회원의 장바구니 품목 ID로 수량 변경 시도
- 기대 결과: `NOT_FOUND`(404)

### TC-115 · 액세스 토큰 만료와 재발급
- 관련: 12번 §2.2, §2.3
- 유형: 정상 / 예외

### TC-116 · 리프레시 토큰 회전과 탈취 구간 단축
- 관련: 12번 §2.2

## N. 접점 검증 전용 (X1~X8)

이 그룹은 `15-review-report.md`의 X1~X8 판정 근거가 된 테스트다. 문서 수정 후 재실행해 결함이 해소됐는지 확인하는 회귀 테스트로 쓴다.

### TC-117 · [X1] 오류 코드 - 화면 상태 1:1 대응 회귀 검증 (재검토 2026-08-29 결과 반영)
- 관련: 06번 §5, 11번 §0.5
- 유형: 예외
- 절차: `OUT_OF_STOCK`, `CANCEL_NOT_ALLOWED`, `ORDER_RESTRICTED`, `INTERNAL_ERROR`, `CART_ITEM_LIMIT_EXCEEDED`, `SLOT_CLOSED`를 각각 유발해 화면에 표시되는 안내가 정의돼 있는지 확인
- 기대 결과: 6개 코드 모두 06번 §5 "예외 상태 정의 위치" 표와 각 화면 상세에 대응 문구가 정의돼 있다(`INTERNAL_ERROR`→SC-004·SC-005·SC-007, `CART_ITEM_LIMIT_EXCEEDED`→SC-003·SC-004, `SLOT_CLOSED`→SC-006·SC-007). 15번 문서 X1 결함은 06 수정으로 해소됨

### TC-118 · [X2] 선점 만료 중간 상태의 고객 조작 불가 확인
- 관련: 13번 §2.2, SC-005·006·007
- 유형: 동시성
- 절차: `orders.status = PENDING`이지만 `inventory_holds`가 이미 `EXPIRED`로 회수된 최대 30초 구간에 고객이 결제·시간대 지정을 시도
- 기대 결과: 두 요청 모두 `HOLD_EXPIRED`(409)로 종결되고, 화면은 이미 클라이언트 타이머가 0:00에 도달한 시점에 만료 시트를 띄운 상태라 추가 조작 자체가 불가능하다(모순 없음)

### TC-119 · [X3] 취소 재전송 화면 정의 (TC-098 참조, 재검토 2026-08-29 결과 반영)
- 관련: FR-029, SC-011
- 유형: 예외
- 비고: TC-098과 동일. X3는 06 문서 수준에서 해소됐고, 본 TC는 회귀 확인용으로 유지한다(와이어프레임 데모의 3분기 미구현은 15번 §4 참고, 비차단)

### TC-120 · [X4] 관리자 세션 수명과 운영 시나리오
- 관련: 12번 §2.1, SC-101~113
- 유형: 정상
- 절차: 관리자가 30분 이상 매장에서 연속 조작(SC-111 픽업 준비 → SC-109 픽업 완료 반복)
- 기대 결과: 액세스 토큰이 30분마다 조용히 재발급되어 화면 흐름이 끊기지 않는다. (보안 정책 상 세션이 과도하게 길게 유지되는 문제는 기능 결함이 아니라 T2/AU-U1 정책 결정 사항으로 별도 처리)

### TC-121 · [X5] 락 타임아웃의 화면 노출 (TC-110 참조, 재검토 2026-08-29 결과 반영)
- 비고: TC-110과 동일. X5는 06 수정(SC-004·SC-005 `INTERNAL_ERROR` 오류 상태 추가)으로 해소됐고, 본 TC는 회귀 확인용으로 유지한다

### TC-122 · [X6] 정원 점유 시점과 화면 표시 일치
- 관련: BR-016, SC-006, API-020
- 유형: 정상
- 절차: 슬롯에 PENDING 주문 5건(미결제)과 CONFIRMED 주문 4건이 있는 상태에서 시간대 목록 조회
- 기대 결과: `reservedCount = 4`(PENDING은 집계에서 제외)로 표시되어 실제 정원 점유 시점(결제 성공)과 화면 표시가 일치한다

### TC-123 · [X7] 재고 이력 사유 집합 (TC-084 참조, 재검토 2026-08-29 결과 반영)
- 비고: TC-084와 동일. X7은 03·06 수정(사유 7종 재정의, "노쇼 미복구" 제거)으로 해소됐고, 본 TC는 회귀 확인용으로 유지한다

### TC-125 · [접점] 결제 직전 예약 마감(`SLOT_CLOSED`) 화면 노출 확인
- 관련: FR-023, FR-026, SC-007, API-022, BR-015
- 유형: 예외 / 사용자: 고객
- 절차: 시간대 선택 완료 후(SC-006 → SC-007 진입), 결제 요청 직전에 해당 시간대가 예약 마감(시작 30분 전 경과)되도록 시간을 진행시킨 뒤 `결제하기` 실행
- 기대 결과: API-022 4단계 재검사에서 `SLOT_CLOSED`(409)를 반환하고, SC-007은 "오류(결제 직전 예약 마감)" 시트로 `선택한 시간대의 예약이 방금 마감됐어요` + `다른 시간대 고르기`를 노출해 SC-006으로 유도한다. 결제 시도 자체가 기록되지 않아 재시도 횟수를 차감하지 않는다. 06 신규 보강분(X1 관련)의 회귀 확인용 TC다

### TC-124 · [X8] 마감 자동 전환의 이력 노출 여부
- 관련: 12번 §4.6, BATCH-02, SC-106
- 유형: 예외
- 절차: 상품이 BATCH-02로 자동 CLOSED 전환된 뒤 SC-106(재고 변경 이력) 및 상품 수정 이력(API-107)에 해당 사건이 어떻게 나타나는지 확인
- 기대 결과(현재 설계 기준): `product_stocks`는 변화가 없으므로 SC-106에는 애초에 해당 항목이 나타나지 않는다(빈칸 노출 문제 없음). 다만 `product_change_logs`에도 기록되지 않아(actor_id NOT NULL 제약, 12번 AU-4) 자동 마감 전환에 대한 감사 이력 자체가 어디에도 남지 않는다 — 이는 화면 결함이 아니라 감사 추적 공백이며 T7로 이미 식별된 사항이다
