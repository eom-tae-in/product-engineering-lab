## 한 줄 요약
360px 모바일 기준의 레이아웃 원칙, 공통 컴포넌트 규격, 화면 상태(빈·로딩·오류) 표현 방식, 문구 사전을 정의해 `06-screen-list.md`의 화면을 일관된 UI로 옮길 수 있게 한다.

## 1. 레이아웃 원칙

### 1.1 화면 구조

```
┌─────────────────────────────┐  0
│ 앱 바 (56px)                │  뒤로 / 제목 / 보조 액션
├─────────────────────────────┤  56
│ (선택) 상태 배너 · 타이머    │  40~56px, 고정
├─────────────────────────────┤
│                             │
│ 스크롤 영역                  │  좌우 16px
│                             │
├─────────────────────────────┤
│ 하단 고정 액션 바 (72px)     │  또는 탭 바 (56px)
└─────────────────────────────┘  640
```

### 1.2 고정 영역 사용 규칙

| 영역 | 사용 화면 | 규칙 |
|---|---|---|
| 하단 탭 바 (4개) | SC-001, SC-004, SC-009, SC-014 | 홈 / 장바구니 / 주문 내역 / 마이페이지. 아이콘 + 라벨, 탭 하나당 88 × 56px |
| 하단 액션 바 | SC-003, SC-004, SC-005, SC-006, SC-007, SC-010, SC-012, SC-013, SC-110 | 주요 액션 1개. 금액이 걸린 화면은 금액을 왼쪽, 버튼을 오른쪽에 둔다 |
| 상단 고정 타이머 | SC-005, SC-006, SC-007 | 선점 잔여 시간. 스크롤해도 항상 보인다 |
| 상단 고정 배너 | SC-001(주문 제한), SC-003(마감 안내), SC-004(구매 불가 안내) | 최대 2줄. 3줄을 넘으면 시트로 옮긴다 |

하단 탭 바와 하단 액션 바를 같은 화면에 동시에 두지 않는다. SC-004는 액션 바를 쓰고 탭 바는 그 아래로 겹치지 않게 액션 바만 노출한다.

### 1.3 스크롤 없이 보여야 하는 요소

| 화면 | 첫 화면(640px) 안에 반드시 보이는 것 |
|---|---|
| SC-001 | 검색창, 정렬 바, 첫 카드의 할인가·할인율·잔여 수량 |
| SC-003 | 상품명, 할인가, 할인율, 잔여 수량, 마감 시각, 담기 버튼 |
| SC-004 | 첫 품목 가격·수량, 결제 예정 금액, 주문하기 버튼 |
| SC-005 | 선점 타이머, 결제 확정 금액, 다음 단계 버튼 |
| SC-006 | 선점 타이머, 날짜 선택 2개, 시간대 칩 6개 이상, 결제 버튼 |
| SC-007 | 픽업 시간대, 결제 확정 금액, 남은 재시도 횟수(실패 시), 결제 버튼 |
| SC-008 | 픽업 번호, 픽업 날짜·시간대, 취소 가능 마감 시각 |
| SC-010 | 상태 배지, 픽업 번호, 픽업 시간대, 취소 가능 여부 |
| SC-109 | 번호 입력창, 조회 결과 요약, 픽업 완료 버튼 |

### 1.4 정보 밀도

| 화면 유형 | 한 화면에 담는 주요 정보 개수 |
|---|---|
| 상품 카드 (SC-001, SC-002) | 카드 1장당 7개 (상품명·정가·할인가·할인율·절약액·잔여 수량·마감 시각) |
| 상품 상세 (SC-003) | 9개 |
| 주문서 (SC-005) | 6개 (타이머·품목·단가·수량·합계·픽업 연락처) |
| 관리자 재고 표 (SC-105) | 행당 5개 (상품명 + 4개 수량 값) |
| 관리자 시간대 행 (SC-111) | 행당 4개 (시간대·예약 건수/정원·품목 합계·상태 배지) |

360px에서 한 행에 5개를 넘는 값을 나란히 두지 않는다. 넘으면 2행으로 접는다.

## 2. 공통 컴포넌트

### 2.1 버튼

| 종류 | 배경 / 테두리 | 텍스트 | 높이 | 용도 |
|---|---|---|---|---|
| 주요 | `--color-brand` 채움 | `--color-on-brand` | 52px | 화면당 1개. 결제하기, 주문하기 |
| 보조 | `--color-surface` + `--color-border` 테두리 | `--color-text` | 48px | 취소하지 않기, 다시 시도 |
| 텍스트 | 없음 | `--color-brand` | 44px | 전체 보기, 필터 초기화 |
| 위험 | `--color-surface` + `--color-danger` 테두리 | `--color-danger` | 48px | 전체 취소하기, 관리자 취소 |
| 비활성 | `--color-border` 채움 | `--color-text-weak` | 동일 | 버튼 위에 비활성 사유를 캡션으로 반드시 적는다 |

비활성 버튼은 숨기지 않는다. 왜 못 누르는지 보여야 고객이 다음 행동을 정한다.

### 2.2 배지

| 배지 | 배경 | 텍스트 | 사용처 |
|---|---|---|---|
| 할인율 | `--color-brand-weak` | `--color-brand` | `30% 할인` |
| 소진 임박 | 없음 | `--color-warning` | 잔여 3개 이하 |
| 품절 | `--color-danger-weak` | `--color-danger` | 잔여 0, 판매 중지 |
| 판매 종료 | `--color-border` | `--color-text-weak` | 마감 시각 경과 |
| 주문 상태 | 상태별 (2.3) | — | SC-009, SC-010, SC-108 |

배지 높이 22px, 좌우 여백 8px, `--radius-sm`, `--font-caption`.

### 2.3 주문 상태 배지 표기

| 상태값 | 고객 표기 | 관리자 표기 | 배경 / 텍스트 |
|---|---|---|---|
| PENDING | (고객 목록 미노출) | `결제 대기` | `--color-border` / `--color-text-weak` |
| CONFIRMED | `확정` | `확정` | `--color-brand-weak` / `--color-brand` |
| READY | `준비 완료` | `준비 완료` | `--color-brand-weak` / `--color-brand` |
| COMPLETED | `픽업 완료` | `픽업 완료` | `--color-border` / `--color-text` |
| CANCELED | `취소` | `취소` | `--color-border` / `--color-text-weak` |
| NO_SHOW | `노쇼` | `노쇼` | `--color-danger-weak` / `--color-danger` |
| EXPIRED | (기본 목록 미노출) | `선점 만료` | `--color-border` / `--color-text-weak` |
| FAILED | `결제 실패` | `결제 실패` | `--color-danger-weak` / `--color-danger` |

영문 상태값은 고객 화면에 노출하지 않는다. 관리자 화면에서도 한국어 표기를 쓰되 필요 시 캡션으로 영문을 병기할 수 있다.

### 2.4 상품 카드 (SC-001, SC-002)

```
┌────────────────────────────────┐  328 × 약 170 (내용에 따라 가변)
│ ┌────────┐  삼겹살 500g        │  이미지 96×96 (회색 플레이스홀더)
│ │        │  12,000원(취소선)   │  --font-caption / --color-text-weak
│ │  이미지 │  8,400원            │  --font-price / --color-discount
│ │        │  [30% 할인] 3,600원 아낌
│ └────────┘  남은 수량 2개 · 소진 임박
│             오늘 21:00 마감
└────────────────────────────────┘
```

- 카드 배경 `--color-surface`, `--radius-lg`, `--shadow-card`, 안쪽 여백 16px
- 카드 사이 12px
- 카드 높이는 고정값이 아니라 내용(상품명·정가·할인가·할인율 배지+절약액·잔여 수량·마감 시각 6줄 텍스트)에 따라 정해지며 대표값은 **약 170px**다(실제 와이어프레임 `sc-001-home-product-list.html` 기준). 표시 항목을 줄여 특정 높이에 맞추지 않는다
- 품절 카드: 이미지와 텍스트 불투명도 0.55, 우상단 `품절` 배지, 정렬 결과에서 목록 끝으로 밀린다
- 할인율 0%(마감 24시간 초과) 카드: 정가 취소선과 할인 배지를 표시하지 않고 가격 하나만 둔다. 이 경우 텍스트 줄이 줄어 카드 높이가 약 170px보다 낮아진다

### 2.5 선점 타이머 바 (SC-005, SC-006, SC-007)

| 남은 시간 | 배경 | 텍스트 | 문구 |
|---|---|---|---|
| 10:00 ~ 1:01 | `--color-brand-weak` | `--color-brand` | `선점 시간 09:58 남음` |
| 1:00 ~ 0:01 | `--color-warning-weak` | `--color-warning` | `01:00 남음 · 시간은 연장되지 않아요` |
| 0:00 | 타이머 대신 만료 시트 전환 | — | — |

- 높이 44px, 화면 상단 고정
- 초 단위로 갱신하고 서버가 준 만료 시각을 기준으로 계산한다. 기기 시각을 쓰지 않는다
- 색만으로 임박을 알리지 않는다. 문구를 함께 바꾼다

### 2.6 픽업 시간대 칩 (SC-006)

3열 그리드, 칩 크기 100 × 56px, 칩 사이 8px.

| 칩 상태 | 배경 | 테두리 | 보조 라벨 |
|---|---|---|---|
| 선택 가능 | `--color-surface` | `--color-border` | `4/20` |
| 선택됨 | `--color-brand` | `--color-brand` | `4/20` (흰색) |
| 예약 마감 | `--color-bg` | `--color-border` | `마감` |
| 정원 마감 | `--color-bg` | `--color-border` | `20/20` |
| 상품 마감 초과 | `--color-bg` | `--color-border` | `상품 마감 이후` |
| 운영 차단 | `--color-bg` | `--color-border` | `운영 중단` |

선택 불가 칩은 불투명도 0.5로 낮추되 목록에서 지우지 않는다. 24개 칩이 항상 같은 자리에 있어야 고객이 시간대를 비교할 수 있다.

### 2.7 하단 시트

| 용도 | 구성 |
|---|---|
| 확인 요구 | 제목 + 설명 + 보조 버튼 + 주요·위험 버튼 |
| 결과 안내 | 아이콘 없이 제목 + 설명 + 단일 버튼 |
| 차단 안내 | 제목 + 사유 + 기준 시각 + 대안 경로 버튼 |

- 상단 모서리 `--radius-lg`, `--shadow-sheet`
- 배경 딤 `rgba(26,31,28,.4)`
- 선점 만료 시트는 딤을 탭해도 닫히지 않는다. 만료 사실을 반드시 인지시킨다

### 2.8 입력 필드

- 높이 52px, `--radius-md`, 테두리 `--color-border`, 포커스 시 `--color-brand`
- 라벨은 필드 위에 `--font-caption`으로 둔다. 플레이스홀더를 라벨 대신 쓰지 않는다
- 오류 시 테두리 `--color-danger` + 필드 아래 `--color-danger` 캡션
- 수량 조절기: `−` / 숫자 / `+`, 각 44 × 44px, 한계값 도달 시 해당 버튼만 비활성

### 2.9 관리자 표

- 열은 최대 4개. 5개 이상이면 행을 2줄로 접는다
- 숫자 열은 우측 정렬, `tabular-nums`
- 재고 표(SC-105)는 `총 재고 / 판매 가능 / 선점 중 / 확정 판매` 순서를 고정하고, 합계 검증 줄(`총 재고 = 판매 가능 + 선점 중 + 확정 판매`)을 표 아래에 둔다

## 3. 화면 상태 표현 규칙

### 3.1 로딩

| 유형 | 사용처 | 표현 |
|---|---|---|
| 스켈레톤 | 목록·상세 최초 조회 | 실제 레이아웃과 같은 크기의 회색 블록. 개수는 화면당 3~6개 |
| 버튼 인라인 | 결제·저장·취소 실행 | 버튼 라벨을 진행 표시로 바꾸고 재탭을 막는다 |
| 전체 화면 | 주문서 생성(SC-005 진입)만 | `재고를 확보하는 중이에요`. 이 동안 이탈 버튼을 노출하지 않는다 |

스피너만 도는 화면을 만들지 않는다. 무엇을 기다리는지 문구로 적는다.

### 3.2 빈 상태

구성 3요소: **사실 문구 + 이유·조건 + 다음 행동 버튼**

| 화면 | 사실 문구 | 이유·조건 | 다음 행동 |
|---|---|---|---|
| SC-001 | `지금 판매 중인 상품이 없어요` | `영업시간은 10:00~22:00입니다` | `새로고침` |
| SC-002 | `"OO"와 일치하는 판매 중 상품이 없어요` | — | `전체 상품 보기` |
| SC-004 | `장바구니가 비어 있어요` | — | `마감 할인 상품 보러 가기` |
| SC-006 | `지금은 예약할 수 있는 픽업 시간대가 없어요` | 사유 3종 구분 표시 | `주문서 포기하고 장바구니로` |
| SC-009 | `아직 주문이 없어요` | — | `마감 할인 상품 보러 가기` |
| SC-009(필터) | `"취소"에 해당하는 주문이 없어요` | — | `전체 보기` |
| SC-103 | `등록된 상품이 없어요` | — | `상품 등록하기` |
| SC-108 | `조건에 맞는 주문이 없어요` | 적용된 필터 나열 | `필터 초기화` |
| SC-111 | `이 날짜에 예약된 픽업이 없어요` | — | 날짜 전환 |
| SC-112 | `오늘 노쇼로 처리된 주문이 없어요` | — | `전환 예정 보기` |

### 3.3 오류

구성 3요소: **무엇이 안 됐는지 + 왜 + 무엇을 하면 되는지**

| 오류 유형 | 표현 위치 | 재시도 |
|---|---|---|
| 조회 실패 | 콘텐츠 영역 대체 | `다시 시도` 버튼. 직전 데이터가 있으면 지우지 않는다 |
| 검증 실패(입력) | 해당 필드 아래 캡션 | 버튼 비활성 유지 |
| 규칙 위반(재고·시간·상태) | 하단 시트 | 대안 경로 버튼 (다른 시간대 고르기, 장바구니로) |
| 권한 없음 | 전체 화면 | 데이터를 어떤 형태로도 노출하지 않는다 |
| 통신 무응답(결제) | 하단 시트 | 실패로 처리했음을 명시하고 남은 재시도 횟수를 함께 표시 |

오류 문구에 기술 용어(`500`, `timeout`, `null`)를 쓰지 않는다.

### 3.4 상태 우선순위

한 화면에 여러 상태가 동시에 성립하면 아래 순서로 하나만 표시한다.

| 순위 | 상태 | 이유 |
|---|---|---|
| 1 | 권한 없음 | 데이터를 보여 주면 안 된다 |
| 2 | 선점 만료 | 이후 모든 액션이 무효다 |
| 3 | 주문 제한 | 주문서를 만들 수 없다 |
| 4 | 오류 | 현재 데이터가 신뢰할 수 없다 |

## 7. 와이어프레임 제작 지침

`wireframes/` 산출물이 지켜야 할 조건이다.

| # | 조건 |
|---|---|
| 1 | 파일명은 `sc-###-화면명.html`로 화면 ID와 1:1 대응한다 |
| 2 | 각 파일 상단에 화면 ID·이름·사용자·관련 FR을 적은 메타 바를 두고 프로토타입 본체와 시각적으로 구분한다 |
| 3 | 상태 전환 토글로 기본 / 로딩 / 빈 상태 / 오류 / 품절(또는 화면별 특수 상태)을 전환할 수 있게 한다 |
| 4 | 색상값은 `08-brand-guide.md` 8장 토큰 블록을 그대로 복사해 쓰고 새 색을 만들지 않는다 |
| 5 | 상품 이미지는 회색 박스 + 라벨로 대체한다. 실제 사진을 넣지 않는다 |
| 6 | 애니메이션·트랜지션·반응형 브레이크포인트를 넣지 않는다 |
| 7 | `localStorage`, `sessionStorage`를 쓰지 않는다. 상태는 JS 변수로만 다룬다 |
| 8 | 360px에서 가로 스크롤이 발생하지 않는다 |
| 9 | 고객 주문 흐름(SC-001 → SC-003 → SC-004 → SC-005 → SC-006 → SC-007 → SC-008)이 클릭으로 끝까지 진행된다 |
| 10 | 예외 경로 최소 1개(결제 실패, 선점 만료)에 클릭으로 도달할 수 있다 |
| 11 | 데이터는 대표 사례를 쓰되 기획 문서의 수치(10분, 24개 슬롯, 정원 20건, 할인율 0·30·50·70%, 3회 재시도)와 모순되지 않게 한다 |
