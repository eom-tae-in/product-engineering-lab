## 6. MVP 성공 판정 (01번 §6 지표와 연결)

01-service-plan.md §6의 지표(M1~M9)는 공개 후 8주 운영 데이터로만 판정 가능하므로 G3 시점에는 "측정 가능한 구조가 갖춰졌는가"만 확인한다.

| 지표 | 측정에 필요한 데이터 소스 | G3 확인 결과 |
|---|---|---|
| M1 마감 소진율 | `stock_ledgers`(CONFIRM 누적) ÷ 상품 등록 수량 | 10번 스키마로 산출 가능 |
| M2 주문 전환율 | 상품 상세 조회 로그 ÷ CONFIRMED 건수 | API-011 호출 로그 + `orders` 필요(로그 수집은 구현 단계 사항) |
| M3 픽업 완료율 | `orders.status = COMPLETED` ÷ CONFIRMED 도달 건수 | 10번 스키마로 산출 가능 |
| M4 노쇼율 | `orders.status = NO_SHOW` ÷ CONFIRMED 도달 건수 | 10번 스키마로 산출 가능 |
| M5 선점 만료율 | `HOLD_EXPIRE` 원장 건수 ÷ 생성된 주문서 수 | 10번 스키마로 산출 가능 |
| M6 결제 재시도 성공률 | `payment_attempts` 시도 이력 | 10번 스키마로 산출 가능 |
| M7 고객 취소율 | `CANCELED` ÷ CONFIRMED 도달 건수 | 10번 스키마로 산출 가능 |
| M8 재구매율 | 회원별 COMPLETED 건수 집계 | 10번 스키마로 산출 가능 |
| M9 픽업 시간대 분산도 | `pickup_slots.reserved_count` 일별 분포 | 10번 스키마로 산출 가능 |

**결론: M2(주문 전환율, 조회 세션 로그 필요)를 제외한 8개 지표는 현재 데이터 모델만으로 즉시 산출 가능하다.** M2는 별도 조회 이벤트 로깅이 구현 단계에서 추가돼야 하며, 이는 설계 문서의 결함이 아니라 구현 시 확인할 사항이다.

## 7. G4 최종 판정 (2026-08-29 재검토 반영)

`15-review-report.md`의 「재검토 (2026-08-29)」 절과 §4의 게이팅 해소 확인 결과를 종합하면 다음과 같다.

- §4의 G-1~G-6 전항목이 해소됐고, 새로운 게이팅 사유를 만들지 않았다(15번 §4 "새로 깨진 부분 점검" 참고 — 발견된 2건 모두 비차단으로 분류됨).
- 01~14 전체 설계 문서가 승인 상태이며, 15~17번 산출물도 이번 재검토로 최신화됐다.
- §5의 P-1~P-5는 기능·데이터 정합성에 영향이 없는 정책/형식 확정 대기 항목으로, 이전과 동일하게 MVP 출시를 막지 않는다.

**결론: G4(발행)로 진행 가능하다.**
