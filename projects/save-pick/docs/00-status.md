### 설계와 어긋나 보류했던 항목 — 3건 해소, 1건 미구현 확정 (2026-09-03)

구현 당시 "API가 정보를 주지 않아" 보류했던 4건을 재검토했다. 세 건은 해소했고 한 건은 첫 버전에서 제외하기로 확정했다.

| 화면 | 항목 | 결과 |
|---|---|---|
| SC-011 · SC-110 | 마감 후 `재고로 되돌리지 않아요` 분기 (BR-019) | **해소** — `order_items.product_closing_at`(주문 시점 스냅샷)이 이미 있어 API-024·114 응답에 `productClosingAt`을 노출하고 분기했다 |
| SC-108 | 픽업 시간대 필터 | **해소** — SC-111 슬라이스가 만든 API-118 클라이언트로 시간대 목록을 얻을 수 있게 됐다. API 변경 없음 |
| SC-106 | 관련 주문 번호 → SC-110 링크 | **해소** — 원장 엔티티가 이미 `order_id`를 갖고 있어 API-111 응답에 `orderId`를 추가했다 |
| SC-001 | `상품 N건이 마감돼 목록에서 빠졌어요` | **미구현 확정** — 사유와 되살릴 조건은 06 SC-001 구현 메모 참고 |

셋 중 둘(SC-108·SC-106)은 API를 바꿀 필요조차 없었고, 나머지 하나도 데이터가 이미 DB에 있는데 응답에서만 빠져 있었다. "API가 없다"는 판단이 실제로는 "찾아보지 않았다"였던 셈이다.

SC-001만 성격이 다르다 — 데이터가 없어서가 아니라 연속 조회 간 비교(폴링)가 필요한데, 안내 줄 하나를 위한 폴링 비용이 이득보다 크다고 보고 제외했다. 마감 상품은 이미 목록에서 빠지므로 잘못 담을 수는 없다.

06번 자체의 미구현 2건(SC-112 수동 노쇼 처리, SC-102 「재고 이력」 메뉴)도 해당 문서에 사유와 되살릴 조건을 남겼다.
