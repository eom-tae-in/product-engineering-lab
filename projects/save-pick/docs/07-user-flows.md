- 문서 ID: 07

- 최종 갱신: 2026-08-28
- 선행 문서: 01, 02, 03, 04, 05, 06

## 한 줄 요약
고객 흐름 6개와 관리자 흐름 5개를 화면 ID가 붙은 Mermaid 다이어그램으로 분리해 정의하고, 각 흐름의 시작·종료 조건과 예외 경로를 명시한다.

---

## 0. 읽는 방법

- 흐름 ID는 고객 `FL-001~FL-006`, 관리자 `FL-101~FL-105`로 부여한다.
- 노드에는 `06-screen-list.md`의 화면 ID를 함께 적는다.
- 정상 경로는 실선(`-->`), 예외·타임아웃 경로는 점선(`-.->`)으로 그린다.
- 분기 노드에는 판정 조건을 적는다. 판정 기준 시각은 모두 서버 시각(KST)이다 (BR-028).
- **고객 흐름과 관리자 흐름은 별도 다이어그램으로 그리며 한 그림에 합치지 않는다.** 두 흐름의 접점은 6장에서 상태 변화로만 서술한다.

### FL-001 · 상품 탐색부터 주문 확정까지

- 사용자: 고객, 비로그인(탐색·담기까지)
- 시작 조건: 고객이 서비스에 진입한다
- 종료 조건: 주문이 CONFIRMED가 되고 픽업 번호가 발급된다
- 관련 시나리오: CS-01

```mermaid
flowchart TD
    A[홈 · 상품 목록 SC-001] --> B[상품 상세 SC-003]
    A -->|검색| A2[상품 검색 SC-002] --> B
    B -->|수량 선택 후 담기| C[장바구니 SC-004]
    C -->|주문하기| D{로그인 · 주문 가능 · 재고 충분}
    D -.미로그인.-> L[로그인 SC-012 → FL-002]
    D -.재고 부족.-> X1[부족 품목 안내 · 주문서 생성 안 함]
    D -->|모두 통과| E[주문서 작성 SC-005<br/>선점 10분 시작 · 금액 확정]
    E -->|픽업 시간 고르기| F[픽업 날짜·시간대 선택 SC-006<br/>오늘 / 내일 · 30분 단위 24개]
    F -->|시간대 선택| G[결제 확인 SC-007]
    G -->|가상 결제 성공| H[주문 완료 SC-008<br/>픽업 번호 3자리 · 취소 마감 시각]
    H --> I[주문 상세 SC-010]
    E -.10분 경과.-> X2[선점 만료 → FL-003]
    F -.10분 경과.-> X2
    G -.10분 경과.-> X2
    G -.결제 실패.-> X3[결제 실패 → FL-004]
```

**단계별 화면 전이와 상태 변화**

| # | 화면 | 고객 액션 | 주문 상태 | 재고 변화 |
|---|---|---|---|---|
| 1 | SC-001 → SC-003 | 상품 선택 | — | 없음 |
| 2 | SC-003 → SC-004 | 장바구니 담기 | — | 없음 (BR-010) |
| 3 | SC-004 → SC-005 | 주문하기 | (없음) → PENDING | 판매 가능 −N, 선점 중 +N |
| 4 | SC-005 → SC-006 | 픽업 시간 고르기 | PENDING 유지 | 없음 |
| 5 | SC-006 → SC-007 | 시간대 선택 후 결제로 | PENDING 유지 | 없음 |
| 6 | SC-007 → SC-008 | 결제 성공 | PENDING → CONFIRMED | 선점 중 −N, 확정 판매 +N, 정원 +1 |

**분기 조건**

| 분기 | 조건 | 통과 못 하면 |
|---|---|---|
| 로그인 | 인증 상태 | SC-012로 이동 (FL-002) |
| 주문 권한 | 계정이 ALLOWED | SC-004에 제한 안내 시트, 해제 예정 시각 표시 |
| 진행 중 주문서 | 유효한 PENDING 주문서 없음 | `주문서로 이동` 안내 |
| 재고 | 전 품목 잔여 수량 ≥ 담긴 수량 | 부족 품목·수량 안내, 부분 선점 만들지 않음 |
| 픽업 시간대 | 선택 가능한 시간대 1개 이상 | SC-006 전체 빈 상태, 주문 진행 불가 |
| 금액 일치 | 결제 요청 금액 = 주문서 확정 금액 | 결제 진행 안 함, 주문서 재확인 안내 |

### FL-002 · 비로그인 주문 시도와 로그인 복귀

- 사용자: 비로그인
- 시작 조건: 미로그인 상태로 SC-004에서 `주문하기`를 누른다
- 종료 조건: 로그인 또는 가입을 마치고 장바구니 내용이 유지된 채 SC-004로 돌아온다
- 관련 시나리오: CS-01 6~8단계

```mermaid
flowchart TD
    A[장바구니 SC-004] -->|주문하기| B{로그인 상태인가?}
    B -->|예| Z[주문서 작성 SC-005]
    B -->|아니오| C[로그인 SC-012<br/>담은 상품은 유지된다고 안내]
    C -->|기존 계정| D{인증 성공?}
    D -->|성공| A
    D -.비밀번호 불일치.-> E[이메일 또는 비밀번호 확인 안내<br/>무엇이 틀렸는지 구분하지 않음]
    E -.-> C
    D -.연속 5회 실패.-> F[10분 잠금 안내 · 해제 시각 표시]
    C -->|계정 없음| G[회원가입 SC-013]
    G --> H{가입 검증}
    H -.이메일 중복.-> I[이미 가입된 이메일 안내 → 로그인]
    I -.-> C
    H -.형식·길이 오류.-> J[항목별 안내]
    J -.-> G
    H -->|통과| A
```

**규칙 반영**
- 가입 완료 시 별도 로그인 없이 인증 상태가 된다 (FR-001).
- 미로그인 장바구니는 로그인 후에도 그대로 유지된다.
- 가입만으로 관리자 권한은 부여되지 않으며 관리자 화면에 도달할 수 없다 (FR-004).

### FL-003 · 선점 만료 예외

- 사용자: 고객
- 시작 조건: PENDING 주문서 생성 후 10분이 지난다 (연장 없음)
- 종료 조건: 주문이 EXPIRED가 되고 선점 수량이 판매 가능 재고로 복구된다
- 관련 시나리오: CS-02

```mermaid
flowchart TD
    A[주문서 작성 SC-005<br/>타이머 10:00 시작] --> B{남은 시간}
    B -->|1분 초과| C[정상 진행 SC-006 → SC-007]
    B -.1분 이하.-> D[만료 임박 배너<br/>1분 뒤 선점이 풀려요 · 연장 없음]
    D -.-> C
    B -.0초 도달.-> E[선점 만료 시트<br/>SC-005 · SC-006 · SC-007 공통]
    C -.결제 시도 시 서버 만료 판정.-> E
    E --> F[주문 PENDING → EXPIRED<br/>선점 중 −N · 판매 가능 +N]
    F --> G[장바구니 SC-004로 복귀]
    G -->|다시 주문하기| H{현재 재고와 현재 할인가로 재검증}
    H -->|충분| I[새 주문서 SC-005<br/>새 10분 · 새 확정 금액]
    H -.부족.-> J[부족 품목과 부족 수량 안내]
    J --> K[구매 불가 품목 삭제 후 재시도]
    K --> H
```

**화면별 만료 표현**

| 화면 | 만료 전 | 만료 시점 |
|---|---|---|
| SC-005 | 상단 고정 타이머 `mm:ss`, 1분 이하 시 경고색 | 화면을 덮는 만료 시트, 뒤로가기로 주문서 복귀 불가 |
| SC-006 | 상단 고정 타이머 유지 | 동일 시트. 선택하던 시간대는 유지하지 않는다 |
| SC-007 | 결제 버튼 위 남은 시간 표시 | 결제 요청을 보내지 않고 만료 시트로 전환 |

**규칙 반영**
- EXPIRED에서 PENDING으로 되돌아가지 않는다 (05-state-rules 2.3).
- 만료된 수량은 만료 시점에 이미 다른 고객의 잔여 수량으로 반영된다 (BR-008).
- 재시도 횟수가 남아 있어도 만료 후에는 결제할 수 없다 (BR-012).

### FL-004 · 가상 결제 실패와 재시도

- 사용자: 고객
- 시작 조건: SC-007에서 결제 요청이 실패 결과 또는 무응답을 반환한다
- 종료 조건: 재시도로 CONFIRMED가 되거나 3회째 실패로 FAILED가 되고 선점이 즉시 해제된다
- 관련 시나리오: CS-03

```mermaid
flowchart TD
    A[결제 확인 SC-007] -->|결제하기| B[결제 요청 중<br/>버튼 재탭 차단]
    B -->|성공| C[주문 완료 SC-008<br/>PENDING → CONFIRMED]
    B -.실패 1회.-> D[실패 시트<br/>남은 선점 08:12 · 2번 더 시도 가능]
    B -.무응답.-> D2[응답 없음 → 실패로 처리<br/>시도 횟수 1회 차감]
    D2 -.-> D
    D -->|다시 결제하기| B
    B -.실패 2회.-> E[실패 시트<br/>남은 선점 06:40 · 1번 더 시도 가능<br/>남은 횟수 경고색]
    E -->|다시 결제하기| B
    B -.실패 3회.-> F[주문 종료 화면<br/>PENDING → FAILED · 선점 즉시 해제]
    F --> G[장바구니 SC-004]
    G -->|다시 주문하기| H[새 주문서 SC-005]
    D -.선점 만료가 먼저 옴.-> I[만료 시트 → FL-003]
    E -.선점 만료가 먼저 옴.-> I
```

**재시도 안내에 반드시 표시하는 값**

| 시도 | 안내 문구 | 남은 재시도 |
|---|---|---|
| 1회 실패 | `결제가 완료되지 않았어요. 선점은 08:12 남았고 2번 더 시도할 수 있어요` | 2 |
| 2회 실패 | `1번 더 시도할 수 있어요` (경고색) | 1 |
| 3회 실패 | `주문이 종료됐어요. 선점한 수량은 다시 판매 가능해졌어요` | 0 |

**규칙 반영**
- 재고 복구 시점은 `3회째 실패`와 `선점 만료` 중 먼저 오는 시점이다 (BR-012).
- FAILED 주문에는 픽업 번호를 발급하지 않는다 (FR-025).
- 하나의 주문에 성공 기록은 최대 1개이며 성공 이후 추가 결제 요청을 받지 않는다.

### FL-005 · 주문 취소

- 사용자: 고객
- 시작 조건: CONFIRMED 또는 READY 주문의 상세(SC-010)를 연다
- 종료 조건: 주문이 CANCELED가 되거나 취소 불가 사유를 확인한다
- 관련 시나리오: CS-05, CS-06

```mermaid
flowchart TD
    A[주문 내역 SC-009] --> B[주문 상세 SC-010]
    B --> C{현재 상태}
    C -.COMPLETED.-> D1[취소 버튼 숨김 · 픽업 완료 시각 표시]
    C -.CANCELED.-> D2[취소 완료 안내 · 취소 주체와 사유]
    C -.NO_SHOW.-> D3[노쇼 안내 → FL-006]
    C -->|CONFIRMED 또는 READY| E{현재 시각 < 픽업 시작 1시간 전?}
    E -.아니오.-> F[취소 버튼 비활성<br/>19:00에 취소 가능 시각이 지났어요<br/>매장 문의 안내]
    E -->|예| G[주문 취소 확인 SC-011<br/>전체 취소만 가능함을 안내]
    G -->|취소하지 않기| B
    G -->|전체 취소하기| H{상품 마감 시각 경과?}
    H -->|마감 전| I[CANCELED · 판매 가능 재고 +N<br/>픽업 정원 1건 반납]
    H -->|마감 후| J[CANCELED · 재고 복구 안 함<br/>총 재고에서 폐기로 기록 · 정원 1건 반납]
    I --> K[주문 상세 SC-010 · 취소 완료 표시]
    J --> K
    G -.취소 직전 마감 시각 경과.-> L[방금 취소 가능 시각이 지났어요<br/>취소 실행 안 함]
    L -.-> B
```

**규칙 반영**
- 부분 취소는 없다. 항상 주문 전체가 취소된다 (BR-024).
- 픽업 시간대 정원은 취소 시점과 무관하게 항상 1건 반납한다 (BR-019).
- 여러 품목 중 일부만 마감 시각이 지난 경우 마감 전 품목만 복구한다.

### FL-006 · 노쇼 결과 확인과 주문 제한

- 사용자: 고객
- 시작 조건: 픽업 시간대 종료 후 30분 유예가 지난 시점에 주문이 CONFIRMED 또는 READY 상태다
- 종료 조건: 고객이 NO_SHOW 결과와 누적 횟수, 제한 해제 예정 시각을 확인한다
- 관련 시나리오: CS-07

```mermaid
flowchart TD
    A[확정 주문 · 픽업 20:00~20:30] --> B{20:30 시점}
    B -->|미수령| C[CONFIRMED 유지 · 유예 30분<br/>SC-010에 21:00 노쇼 전환 예정 표시]
    C -.21:00 도달 · 시스템 판정.-> D[NO_SHOW 전환<br/>환불 없음 · 재고 복구 없음 · 픽업 번호 무효]
    C -->|유예 내 방문| E[관리자가 픽업 완료 처리 → COMPLETED]
    D --> F[주문 내역 SC-009<br/>노쇼 배지]
    F --> G[주문 상세 SC-010<br/>21:00 노쇼 판정 · 환불 없음 안내]
    G --> H{최근 30일 노쇼 3회 도달?}
    H -->|아니오| I[마이페이지 SC-014<br/>최근 30일 노쇼 2회 표시]
    H -->|예| J[계정 ALLOWED → RESTRICTED]
    J --> K[SC-001 상단 배너 · SC-014 제한 카드<br/>2026-09-04 19:00까지 새 주문 불가]
    K -.주문 시도.-> L[SC-004 제한 안내 시트<br/>주문서 생성 안 함]
    K -->|7일 경과| M[RESTRICTED → ALLOWED<br/>별도 조작 없이 주문 가능]
    K --> N[상품 조회 · 장바구니 담기 · 기존 주문 취소는 그대로 가능]
```

**규칙 반영**
- 노쇼 수량은 확정 판매로 남고 잔여 수량으로 복구되지 않는다 (BR-022).
- 제한 상태에서도 로그인, 조회, 담기, 기존 확정 주문 취소는 가능하다 (05-state-rules 7.4).
- 관리자가 제한을 즉시 해제하는 기능은 첫 버전에 없다.

### FL-101 · 개점 · 상품과 재고 등록

- 사용자: 관리자
- 시작 조건: 관리자가 관리자 진입 주소로 로그인한다
- 종료 조건: 상품이 ON_SALE이 되어 고객 목록에 노출되고 할인율이 자동 적용된다
- 관련 시나리오: AS-01, AS-02

```mermaid
flowchart TD
    A[관리자 로그인 SC-101] --> B[관리자 홈 SC-102]
    B --> C[상품 관리 목록 SC-103]
    C -->|상품 등록| D[상품 등록·수정 SC-104<br/>상품명·설명·단위·정가·마감 시각·최대 수량]
    D --> E{입력 검증}
    E -.마감 시각이 과거.-> F1[마감 시각은 현재 이후로 안내 · 저장 안 함]
    E -.마감 시각 22:00 초과.-> F2[영업 종료 시각 초과 안내]
    E -.정가 100원 미만.-> F3[정가 하한 안내]
    E -->|통과| G[DRAFT 저장 · 고객 노출 없음]
    G --> H[재고 현황·조정 SC-105<br/>총 재고 20개 등록]
    H --> I{ON_SALE 전환 가능?}
    I -.재고 미등록.-> J[재고를 먼저 등록해야 판매할 수 있어요]
    I -->|재고 1 이상| K[SC-103에서 DRAFT → ON_SALE]
    K --> L[고객 목록 SC-001 즉시 노출<br/>할인율 자동 적용]
    L --> M[할인 구간 정책 SC-107<br/>현재 30% · 다음 구간 진입 시각 확인]
    H -.실물 수량이 적음.-> N[총 재고 축소 시도]
    N --> O{새 값 ≥ 선점 중 + 확정 판매?}
    O -->|예| P[반영 · 판매 가능 재계산]
    O -.아니오.-> Q[확정 6개 · 선점 2개로 8개 미만 불가<br/>최소 가능 값 안내]
    P -.즉시 판매 중지 필요.-> R[SC-103에서 ON_SALE → HIDDEN<br/>신규 주문서만 차단 · 기존 주문 유지]
```

**규칙 반영**
- 등록 직후 상태는 DRAFT이며 고객에게 노출되지 않는다 (FR-040).
- 재고 축소로 이미 만들어진 선점·확정 주문이 취소되지 않는다 (BR-025).
- HIDDEN 전환은 기존 PENDING 선점과 CONFIRMED 주문을 유지한다 (FR-042).
- 마감 시각 도달 시 관리자 조작 없이 CLOSED가 되고 되돌릴 수 없다.

### FL-102 · 픽업 준비와 수령 처리

- 사용자: 관리자
- 시작 조건: 픽업 시간대가 임박해 SC-111 픽업 현황을 연다
- 종료 조건: 주문이 COMPLETED가 되며 재고 수량은 변하지 않는다
- 관련 시나리오: AS-03

```mermaid
flowchart TD
    A[관리자 홈 SC-102] --> B[시간대별 픽업 현황 SC-111<br/>24개 시간대 · 예약 건수 / 정원 20]
    B -->|20:00~20:30 펼치기| C[해당 시간대 주문 목록<br/>픽업 번호 · 고객 이름 · 상태]
    C --> D[주문 상세 관리자 SC-110]
    D -->|준비 완료| E{현재 상태가 CONFIRMED?}
    E -->|예| F[READY · 재고 변화 없음]
    E -.아니오.-> G[CONFIRMED 주문만 준비 완료로 바꿀 수 있어요]
    F --> H[고객 방문]
    D -.준비 완료 생략.-> H
    H --> I[픽업 번호 조회 SC-109<br/>3자리 번호 입력]
    I --> J{조회 결과}
    J -.없음.-> K[해당 영업일에 번호가 없어요]
    J -.이미 COMPLETED.-> L[이미 20:12에 완료된 주문이에요]
    J -.NO_SHOW.-> M[노쇼로 처리돼 수령할 수 없어요]
    J -->|CONFIRMED 또는 READY| N[주문 상세 SC-110]
    N -->|픽업 완료| O[COMPLETED · 완료 시각 기록<br/>재고 변화 없음 · 정원 변화 없음]
    O -.다시 취소 시도.-> P[픽업 완료된 주문은 취소할 수 없어요]
```

**규칙 반영**
- READY는 선택 단계이며 CONFIRMED에서 바로 COMPLETED로 갈 수 있다 (FR-051).
- 노쇼 유예가 끝나기 전이면 픽업 시간대가 지난 주문도 완료 처리할 수 있다 (FR-052).
- 같은 주문을 두 번 완료 처리할 수 없다.

### FL-103 · 관리자 주문 취소

- 사용자: 관리자
- 시작 조건: 운영 사유로 CONFIRMED 또는 READY 주문을 취소해야 한다
- 종료 조건: 사유가 기록된 채 주문이 CANCELED가 되고 재고 복구 여부가 이력에 남는다
- 관련 시나리오: AS-05, CS-06 3단계

```mermaid
flowchart TD
    A[주문 목록 SC-108] --> B[주문 상세 관리자 SC-110]
    B --> C{현재 상태}
    C -.COMPLETED · NO_SHOW · CANCELED.-> D[취소 불가 안내 · 액션 미노출]
    C -->|CONFIRMED 또는 READY| E[관리자 취소 시트<br/>고객 취소 마감과 무관하게 실행 가능]
    E --> F{취소 사유 입력됨?}
    F -.비어 있음.-> G[취소 사유를 입력해주세요 · 실행 안 함]
    F -->|입력됨| H{상품 마감 시각 경과?}
    H -->|마감 전| I[CANCELED · 판매 가능 +N<br/>정원 1건 반납 · 복구 이력 기록]
    H -->|마감 후| J[CANCELED · 재고 복구 안 함<br/>총 재고에서 폐기 기록 · 정원 1건 반납]
    I --> K[고객 주문 상세 SC-010에 취소 사유 표시]
    J --> K
```

**규칙 반영**
- 취소 사유 입력은 필수다 (BR-020).
- 부분 취소는 지원하지 않는다 (BR-024).
- 재고 복구 여부와 그 사유가 재고 변경 이력(SC-106)에 남는다 (FR-047).

- 종료 조건: 자동 전환 결과를 확인하고, 유예가 남은 주문은 필요 시 완료 처리한다

### FL-105 · 픽업 운영 설정 변경

- 사용자: 관리자
- 시작 조건: 영업시간·정원·차단 시간대를 조정해야 한다
- 종료 조건: 변경이 이후 생성되는 주문부터 적용되고 확정 주문은 그대로 유지된다

```mermaid
flowchart TD

    B --> C[영업시간 변경]
    C --> D{종료 시각 > 시작 시각?}
    D -.아니오.-> E[영업 종료 시각은 시작 시각보다 늦어야 해요]
    D -->|예| F[21:00으로 단축 시 경고<br/>21:00 이후 시작 시간대가 신규 선택에서 빠져요<br/>확정 주문은 유지]
    B --> G[정원 변경 20 → 12]
    G --> H{기존 예약이 새 정원 초과?}
    H -->|예| I[이미 15건 예약된 시간대가 있어요<br/>기존 주문은 취소되지 않아요 · 확인 요구]
    H -->|아니오| J[반영]
    I --> J
    B --> K[특정 시간대 차단]
    K --> L[해당 시간대 신규 선택 제외<br/>기존 예약 유지 · SC-111에 운영 중단 배지]
    L -->|차단 해제| M{정원 여유 있음?}
    M -->|예| N[다시 선택 가능]
    M -.없음.-> O[정원 마감으로 표시 유지]
    B --> P[휴무일 지정]
    P --> Q[SC-006 픽업 날짜 선택에서 제외]
    J --> R[이후 생성되는 주문부터 적용]
    F --> R
    L --> R
```

**규칙 반영**
- 운영 설정 변경이 이미 확정된 주문의 픽업 시간을 바꾸거나 취소하지 않는다 (FR-056, FR-057, FR-058).
- 영업시간은 30분 단위로만 설정한다 (BR-014).

## 4. 화면 진입·이탈 정합성

`06-screen-list.md`의 진입·이탈 정의와 본 문서의 전이가 어긋나지 않도록 아래를 확인한다.

| 확인 항목 | 결과 |
|---|---|
| 모든 고객 화면에 최소 1개의 진입 경로가 흐름도에 있다 | 충족 (SC-001~SC-015) |
| 모든 관리자 화면에 최소 1개의 진입 경로가 흐름도에 있다 | 충족 (SC-101~SC-113) |
| 종료 상태(COMPLETED·CANCELED·NO_SHOW·EXPIRED·FAILED) 각각에 도달하는 흐름이 있다 | 충족 (FL-001, FL-003, FL-004, FL-005, FL-006, FL-102) |
| 되돌릴 수 없는 전이가 흐름도에서 역방향으로 그려지지 않았다 | 충족 |
| 고객 흐름과 관리자 흐름이 같은 다이어그램에 섞이지 않았다 | 충족 |

## 6. 고객 흐름과 관리자 흐름의 접점

두 흐름은 화면을 공유하지 않고 **상태 변화로만** 만난다.

| # | 접점 | 관리자 쪽 행위 (화면) | 고객 쪽 결과 (화면) |
