# savePick 기능 요구사항

- 문서 ID: 03
- 작성: product-planner
- 최종 갱신: 2026-08-29
- 선행 문서: 01, 02

## 한 줄 요약
savePick 첫 버전이 제공해야 하는 기능을 공통·고객·관리자로 나누어 FR ID와 검증 가능한 완료 조건으로 정의한다.

---

## 0. 읽는 방법

- 우선순위 `필수`는 첫 버전 출시에 반드시 포함한다. `선택`은 일정이 부족하면 미룬다.
- 완료 조건은 관찰 가능한 결과만 쓴다. 각 조건은 하나의 검증만 담는다.
- 관련 규칙의 `BR-###`는 `04-business-rules.md`, 상태값은 `05-state-rules.md`를 따른다.
- 값이 확정되지 않은 숫자는 `[U#]`로 표기하고 문서 끝 「미확정」에 올린다.

## 1. 공통

### FR-001 · 회원가입

- 사용자: 고객
- 관련 규칙: BR-002
- 우선순위: 필수

**설명**
고객이 이메일과 비밀번호로 계정을 만든다.

**완료 조건**
- [ ] 이메일, 비밀번호, 이름, 휴대폰 번호를 입력하면 계정이 생성된다
- [ ] 이미 가입된 이메일로 가입을 시도하면 가입되지 않고 중복 안내를 받는다
- [ ] 이메일 형식이 아닌 값으로는 가입되지 않는다
- [ ] 비밀번호가 8자 미만이면 가입되지 않는다
- [ ] 가입 완료 시 별도 로그인 없이 로그인 상태가 된다
- [ ] 가입만으로는 관리자 권한이 부여되지 않는다

**예외**
- 필수 입력값 중 하나라도 비어 있으면 어떤 항목이 비었는지 알린다

### FR-002 · 로그인 / 로그아웃

- 사용자: 고객, 관리자
- 관련 규칙: BR-002
- 우선순위: 필수

**설명**
등록된 계정으로 로그인하고, 로그아웃으로 인증 상태를 종료한다.

**완료 조건**
- [ ] 등록된 이메일·비밀번호 조합으로 로그인하면 인증 상태가 된다
- [ ] 비밀번호가 틀리면 로그인되지 않고, 이메일과 비밀번호 중 무엇이 틀렸는지 구분해 알리지 않는다
- [ ] 로그아웃하면 인증이 필요한 기능에 접근할 수 없다
- [ ] 로그인 실패가 연속 5회 발생하면 해당 계정의 로그인 시도를 10분간 차단한다
- [ ] 인증 상태는 마지막 활동 후 30일이 지나면 만료된다

**예외**
- 노쇼 누적으로 주문이 제한된 계정도 로그인 자체는 가능하다 (BR-023)

### FR-003 · 회원 정보 조회 및 수정

- 사용자: 고객
- 관련 규칙: BR-002
- 우선순위: 필수

**설명**
고객이 픽업 응대에 필요한 이름과 휴대폰 번호를 확인하고 수정한다.

**완료 조건**
- [ ] 로그인한 고객이 자신의 이름, 이메일, 휴대폰 번호를 확인한다
- [ ] 이름과 휴대폰 번호를 수정하면 이후 생성되는 주문에 반영된다
- [ ] 이메일은 수정할 수 없다
- [ ] 이미 확정된 주문의 픽업 연락처는 수정 결과로 변경되지 않는다

**예외**
- 휴대폰 번호 형식이 올바르지 않으면 저장하지 않는다

### FR-004 · 고객·관리자 권한 분리

- 사용자: 고객, 관리자
- 관련 규칙: BR-002
- 우선순위: 필수

**설명**
계정 권한에 따라 접근 가능한 기능을 나눈다.

**완료 조건**
- [ ] 고객 권한 계정으로 관리자 기능에 접근하면 거부되고 어떤 데이터도 반환되지 않는다
- [ ] 관리자 권한 계정은 모든 관리자 기능을 사용한다
- [ ] 미인증 상태에서 주문·주문 내역·회원 정보 기능에 접근하면 거부된다
- [ ] 미인증 상태에서도 상품 목록·상세·검색은 조회된다

**예외**
- 관리자 계정은 서비스 내 가입 절차로 만들 수 없고 운영자가 직접 부여한다

### FR-005 · 시각 기준 통일

- 사용자: 공통
- 관련 규칙: BR-028
- 우선순위: 필수

**설명**
할인율, 선점 만료, 픽업 마감, 취소 마감, 노쇼 판정에 쓰는 시각 기준을 하나로 맞춘다.

**완료 조건**
- [ ] 모든 시각 판정이 서버 시각(KST)을 기준으로 이뤄진다
- [ ] 고객 기기의 시각을 바꿔도 선점 만료·취소 마감 판정 결과가 달라지지 않는다
- [ ] 화면에 표시되는 남은 시간과 서버 판정 시각의 차이가 5초를 넘지 않는다

**예외**
- 없음

## 2. 고객

### 2.1 상품 탐색

### FR-010 · 상품 목록 조회

- 사용자: 고객
- 관련 규칙: BR-004, BR-006, BR-030
- 우선순위: 필수

**설명**
판매 중인 마감 임박 상품을 목록으로 본다.

**완료 조건**
- [ ] 판매 상태가 ON_SALE인 상품만 목록에 나온다
- [ ] 상품마다 상품명, 정가, 현재 할인가, 할인율, 잔여 수량, 마감 시각이 표시된다
- [ ] 판매 상태가 HIDDEN, DRAFT, CLOSED인 상품은 목록에 나오지 않는다
- [ ] 잔여 수량이 0인 상품은 품절로 표시되고 주문할 수 없다
- [ ] 목록의 기본 정렬은 마감 시각이 빠른 순이다
- [ ] 목록 첫 화면이 2초 내에 표시된다

**예외**
- 판매 중인 상품이 하나도 없으면 빈 목록임을 알린다

### FR-011 · 상품 검색

- 사용자: 고객
- 관련 규칙: BR-030
- 우선순위: 필수

**설명**
상품명으로 판매 중인 상품을 찾는다.

**완료 조건**
- [ ] 검색어가 상품명에 포함된 ON_SALE 상품만 결과에 나온다
- [ ] 대소문자와 앞뒤 공백 차이는 결과에 영향을 주지 않는다
- [ ] 검색 결과에도 목록과 동일하게 할인가와 잔여 수량이 표시된다
- [ ] HIDDEN, CLOSED 상품은 정확한 상품명으로 검색해도 결과에 나오지 않는다
- [ ] 일치하는 상품이 없으면 결과 없음을 알린다

**예외**
- 검색어가 비어 있으면 전체 목록과 같은 결과를 반환한다

### FR-012 · 상품 목록 정렬 및 필터

- 사용자: 고객
- 관련 규칙: BR-004, BR-006
- 우선순위: 선택

**설명**
마감 임박 순, 할인율 높은 순, 가격 낮은 순으로 목록을 정렬하고 품절 상품을 숨긴다.

**완료 조건**
- [ ] 마감 임박 순, 할인율 높은 순, 가격 낮은 순 중 하나를 선택하면 그 기준으로 목록이 재정렬된다
- [ ] 품절 숨기기를 켜면 잔여 수량이 0인 상품이 목록에서 빠진다
- [ ] 정렬 기준을 바꿔도 노출 대상 상품 집합은 달라지지 않는다

**예외**
- 없음

### FR-013 · 상품 상세 조회

- 사용자: 고객
- 관련 규칙: BR-004, BR-006, BR-009
- 우선순위: 필수

**설명**
상품 하나의 상세 정보를 확인한다.

**완료 조건**
- [ ] 상품명, 설명, 판매 단위, 정가, 현재 할인가, 할인율, 잔여 수량, 마감 시각, 1회 주문 최대 수량이 표시된다
- [ ] 잔여 수량이 0이면 장바구니 담기를 실행할 수 없다
- [ ] 마감 시각이 지난 상품의 상세를 열면 판매 종료 안내가 표시되고 담기를 실행할 수 없다
- [ ] 다른 고객의 선점 수량은 잔여 수량에서 제외된 값으로만 보인다

**예외**
- 존재하지 않는 상품을 조회하면 찾을 수 없음을 알린다

### FR-014 · 마감 할인가 표시

- 사용자: 고객
- 관련 규칙: BR-003, BR-004, BR-005
- 우선순위: 필수

**설명**
마감 시각까지 남은 시간에 따라 자동 계산된 할인가를 보여준다.

**완료 조건**
- [ ] 마감까지 남은 시간 구간에 해당하는 할인율이 적용된 가격이 표시된다 (BR-004)
- [ ] 정가, 할인율, 할인가가 함께 표시된다
- [ ] 할인 구간이 바뀌면 최대 60초 안에 새 할인가가 반영된다
- [ ] 마감까지 24시간을 초과해 남은 상품에는 할인율 0%가 적용된 정가가 표시된다
- [ ] 같은 시각에 같은 상품을 조회한 두 고객이 서로 다른 할인가를 보지 않는다

**예외**
- 할인 적용 결과가 100원 미만이면 최저 판매가 100원으로 표시한다 (BR-004)

### FR-015 · 잔여 수량 표시

- 사용자: 고객
- 관련 규칙: BR-006, BR-007
- 우선순위: 필수

**설명**
지금 주문 가능한 수량을 보여준다.

**완료 조건**
- [ ] 표시되는 잔여 수량 = 총 재고 − 선점 중 수량 − 확정 판매 수량이다
- [ ] 다른 고객의 선점이 만료되면 최대 60초 안에 잔여 수량이 늘어난 값으로 반영된다
- [ ] 잔여 수량이 5개 이하이면 소진 임박임을 함께 표시한다
- [ ] 잔여 수량이 음수로 표시되지 않는다

**예외**
- 관리자가 판매를 중지한 상품은 잔여 수량과 무관하게 품절로 표시한다

### 2.2 장바구니

### FR-016 · 장바구니 담기

- 사용자: 고객
- 관련 규칙: BR-009, BR-010
- 우선순위: 필수

**설명**
상품과 수량을 장바구니에 담는다.

**완료 조건**
- [ ] 수량을 지정해 담으면 장바구니에 반영된다
- [ ] 담기만으로는 재고가 선점되지 않고 다른 고객이 보는 잔여 수량도 줄지 않는다
- [ ] 1회 주문 최대 수량(기본 5개)을 넘겨 담을 수 없다
- [ ] 같은 상품을 다시 담으면 수량이 합산되며 최대 수량을 넘지 않는다
- [ ] 장바구니에는 최대 10개 품목까지 담을 수 있다

**예외**
- 담는 시점에 잔여 수량보다 많은 수량을 지정하면 담기지 않고 현재 잔여 수량을 알린다

### FR-017 · 장바구니 조회·수정·삭제

- 사용자: 고객
- 관련 규칙: BR-009
- 우선순위: 필수

**설명**
담긴 상품의 수량을 바꾸거나 빼고 예상 결제 금액을 확인한다.

**완료 조건**
- [ ] 담긴 품목, 각 품목의 현재 할인가, 수량, 합계 금액이 표시된다
- [ ] 수량을 변경하면 합계 금액이 즉시 다시 계산된다
- [ ] 품목을 삭제하면 목록과 합계 금액에서 빠진다
- [ ] 수량을 0으로 바꾸면 해당 품목이 삭제된다
- [ ] 장바구니가 비면 주문하기를 실행할 수 없다

**예외**
- 없음

### FR-018 · 장바구니 유효성 재검증

- 사용자: 고객
- 관련 규칙: BR-005, BR-006, BR-030
- 우선순위: 필수

**설명**
장바구니를 열거나 주문을 시작할 때 담긴 품목이 여전히 구매 가능한지 확인한다.

**완료 조건**
- [ ] 장바구니를 열 때마다 각 품목의 현재 할인가로 금액을 다시 계산한다
- [ ] 담은 뒤 가격이 바뀐 품목은 변경 사실을 표시한다
- [ ] 판매가 종료됐거나 숨김 처리된 품목은 구매 불가로 표시한다
- [ ] 잔여 수량이 담긴 수량보다 적어진 품목은 부족 수량을 표시한다
- [ ] 구매 불가 품목이 남아 있으면 주문서를 만들 수 없다

**예외**
- 구매 불가 품목만 일괄 삭제할 수 있다

### 2.3 주문과 재고 선점

### FR-019 · 주문서 생성 및 재고 임시 선점

- 사용자: 고객
- 관련 규칙: BR-007, BR-008, BR-010, BR-027
- 우선순위: 필수

**설명**
고객이 주문을 시작하면 장바구니 수량만큼 재고를 임시 선점하고 주문서를 만든다.

**완료 조건**
- [ ] 주문서 생성 시 장바구니 전 품목의 수량이 선점되고 주문이 PENDING 상태가 된다
- [ ] 선점된 수량은 다른 고객에게 잔여 수량으로 노출되지 않는다
- [ ] 선점 생성 시점부터 10분의 유효 시간이 부여된다
- [ ] 한 품목이라도 잔여 수량이 부족하면 어떤 품목도 선점하지 않고 주문서를 만들지 않는다
- [ ] 동시에 마지막 1개를 주문한 두 고객 중 한 명만 선점에 성공하고, 다른 한 명은 품절 오류를 받는다
- [ ] 확정된 주문 수량의 합이 관리자가 등록한 총 재고를 초과하지 않는다
- [ ] 유효한 PENDING 주문서를 이미 가진 고객은 두 번째 주문서를 만들 수 없다

**예외**
- 노쇼 누적으로 주문이 제한된 고객은 주문서를 만들 수 없다 (BR-023)

### FR-020 · 선점 잔여 시간 표시와 만료 처리

- 사용자: 고객
- 관련 규칙: BR-007, BR-008
- 우선순위: 필수

**설명**
선점이 언제 끝나는지 알리고, 만료되면 재고를 복구한다.

**완료 조건**
- [ ] 주문 진행 중 남은 선점 시간이 초 단위로 표시된다
- [ ] 만료 [U1]분 전에 곧 만료된다는 안내가 표시된다
- [ ] 유효 시간이 지나면 선점이 해제되고 재고가 복구된다
- [ ] 만료 후 결제를 시도하면 결제가 진행되지 않고 만료 안내를 받는다
- [ ] 만료된 주문은 PENDING에서 EXPIRED로 바뀌며 다시 PENDING으로 되돌아가지 않는다
- [ ] 선점 시간은 연장되지 않는다

**예외**
- 만료 후 다시 주문하면 현재 재고와 현재 할인가로 새 주문서를 만든다

### FR-021 · 주문 금액 확정

- 사용자: 고객
- 관련 규칙: BR-005, BR-029
- 우선순위: 필수

**설명**
주문서 생성 시점의 할인가로 결제 금액을 고정한다.

**완료 조건**
- [ ] 주문서에 표시된 품목별 단가와 합계 금액이 주문서 생성 시점 기준으로 고정된다
- [ ] 주문서 생성 후 할인 구간이 바뀌어도 결제 금액이 달라지지 않는다
- [ ] 결제 요청 금액과 주문서 합계 금액이 다르면 결제를 진행하지 않는다
- [ ] 주문 완료 후 조회한 결제 금액이 주문서 합계 금액과 같다

**예외**
- 주문서가 만료돼 새로 만들면 그 시점의 할인가로 금액을 다시 확정한다

### 2.4 픽업 예약

### FR-022 · 픽업 날짜 선택

- 사용자: 고객
- 관련 규칙: BR-013, BR-017
- 우선순위: 필수

**설명**
픽업할 날짜를 고른다.

**완료 조건**
- [ ] 오늘(D+0)과 내일(D+1) 중에서만 선택할 수 있다
- [ ] 영업하지 않는 날짜는 선택할 수 없다
- [ ] 오늘의 선택 가능한 시간대가 모두 마감된 경우 오늘은 선택할 수 없다
- [ ] D+2 이후 날짜는 선택할 수 없다

**예외**
- 두 날짜 모두 선택 가능한 시간대가 없으면 주문을 진행할 수 없고 사유를 알린다

### FR-023 · 픽업 시간대 선택

- 사용자: 고객
- 관련 규칙: BR-014, BR-015, BR-016, BR-017
- 우선순위: 필수

**설명**
30분 단위 픽업 시간대 중 하나를 고른다.

**완료 조건**
- [ ] 영업시간(10:00~22:00) 안의 30분 단위 시간대만 목록에 나온다
- [ ] 현재 시각 기준 30분 이내에 시작하는 시간대는 선택할 수 없다
- [ ] 예약 건수가 정원(20건)에 도달한 시간대는 선택할 수 없다
- [ ] 주문 품목 중 가장 이른 마감 시각보다 늦게 시작하는 시간대는 선택할 수 없다
- [ ] 관리자가 닫은 시간대는 선택할 수 없다
- [ ] 시간대를 선택하지 않으면 결제를 진행할 수 없다
- [ ] 하나의 주문에는 하나의 시간대만 지정된다

**예외**
- 선택 가능한 시간대가 없으면 그 사유(정원 초과 / 마감 시각 초과 / 영업 종료)를 구분해 알린다

### 2.5 결제와 주문 확정

### FR-024 · 가상 결제 요청

- 사용자: 고객
- 관련 규칙: BR-011, BR-029
- 우선순위: 필수

**설명**
가상 결제를 요청해 성공 또는 실패 결과를 받는다.

**완료 조건**
- [ ] 결제를 요청하면 성공 또는 실패 중 하나의 결과가 반환된다
- [ ] 결제 성공 시 주문이 PENDING에서 CONFIRMED로 바뀐다
- [ ] 결제 성공 시 선점 수량이 확정 차감으로 전환된다
- [ ] 선점이 만료된 주문에는 결제를 요청할 수 없다
- [ ] 같은 주문에 대해 성공 결과가 두 번 기록되지 않는다
- [ ] 결제 결과와 시각이 주문 이력으로 남는다

**예외**
- 결제 요청 중 응답이 없으면 실패로 간주하고 재시도 횟수를 1회 차감한다

### FR-025 · 결제 실패 처리와 재시도

- 사용자: 고객
- 관련 규칙: BR-012
- 우선순위: 필수

**설명**
결제가 실패하면 선점을 유지한 채 재시도를 허용하고, 한도를 넘으면 주문을 종료한다.

**완료 조건**
- [ ] 결제 1회 실패 시 선점이 해제되지 않고 남은 유효 시간이 유지된다
- [ ] 실패 안내에 남은 선점 시간과 남은 재시도 횟수가 표시된다
- [ ] 결제 시도가 누적 3회 실패하면 주문이 FAILED로 바뀌고 선점이 즉시 해제된다
- [ ] 3회 실패 후에는 같은 주문서로 다시 결제할 수 없다
- [ ] 선점 유효 시간이 먼저 끝나면 재시도 횟수가 남아 있어도 결제할 수 없다
- [ ] FAILED 주문으로는 픽업 번호가 발급되지 않는다

**예외**
- 3회 실패 후 다시 주문하려면 주문서를 새로 만든다

### FR-026 · 주문 확정과 픽업 번호 발급

- 사용자: 고객
- 관련 규칙: BR-026
- 우선순위: 필수

**설명**
결제가 성공하면 주문을 확정하고 매장에서 쓸 픽업 번호를 발급한다.

**완료 조건**
- [ ] 주문 확정 시 주문 번호와 픽업 번호가 발급된다
- [ ] 픽업 번호는 같은 영업일 안에서 중복되지 않는다
- [ ] 주문 완료 결과에 픽업 날짜, 시간대, 결제 금액, 취소 가능 마감 시각이 표시된다
- [ ] 확정된 주문의 수량만큼 해당 시간대의 예약 정원이 1건 차감된다
- [ ] 확정되지 않은 주문에는 픽업 번호가 없다

**예외**
- 없음

### 2.6 주문 관리

### FR-027 · 주문 내역 조회

- 사용자: 고객
- 관련 규칙: BR-002
- 우선순위: 필수

**설명**
본인의 주문 목록을 최신순으로 확인한다.

**완료 조건**
- [ ] 본인이 만든 주문만 조회된다
- [ ] 주문마다 주문 번호, 주문 일시, 상태, 픽업 일시, 결제 금액이 표시된다
- [ ] 다른 고객의 주문은 어떤 방법으로도 조회되지 않는다
- [ ] 상태(진행 중 / 완료 / 취소 / 노쇼)로 걸러 볼 수 있다
- [ ] EXPIRED 주문은 기본 목록에 표시하지 않는다

**예외**
- 주문이 없으면 빈 목록임을 알린다

### FR-028 · 주문 상세 조회

- 사용자: 고객
- 관련 규칙: BR-018, BR-026
- 우선순위: 필수

**설명**
주문 하나의 품목과 진행 상태를 확인한다.

**완료 조건**
- [ ] 품목별 상품명, 수량, 확정 단가, 합계 금액이 표시된다
- [ ] 확정된 주문은 픽업 번호, 픽업 날짜·시간대가 표시된다
- [ ] 현재 취소 가능 여부와 취소 가능 마감 시각이 표시된다
- [ ] 상태 변경 이력(확정 / 준비 완료 / 완료 / 취소 / 노쇼)과 각 시각이 표시된다
- [ ] 관리자 취소 건은 취소 사유가 함께 표시된다

**예외**
- 본인 주문이 아니면 조회되지 않는다

### FR-029 · 주문 취소

- 사용자: 고객
- 관련 규칙: BR-018, BR-019, BR-024
- 우선순위: 필수

**설명**
확정된 주문을 픽업 시작 1시간 전까지 고객이 직접 취소한다.

**완료 조건**
- [ ] 픽업 시작 시각 1시간 전까지는 취소가 실행된다
- [ ] 취소하면 주문이 CANCELED로 바뀐다
- [ ] 취소한 수량이 즉시 판매 가능 재고로 복구된다 (BR-019)
- [ ] 취소 시 점유하던 픽업 시간대 정원 1건이 반납된다
- [ ] 픽업 시작 1시간 이내에는 취소가 실행되지 않는다
- [ ] 일부 품목만 취소할 수 없고 주문 전체가 취소된다
- [ ] COMPLETED, NO_SHOW, CANCELED 주문은 다시 취소할 수 없다

**예외**
- 취소 시점에 상품 마감 시각이 지났으면 주문은 취소되되 재고는 복구하지 않는다 (BR-019)

### FR-030 · 취소 가능 여부 안내

- 관련 규칙: BR-018
- 우선순위: 필수

**완료 조건**
- [ ] 주문 확정 결과에 취소 가능 마감 시각이 표시된다
- [ ] 취소 마감 시각이 지나면 취소를 실행할 수 없는 상태로 표시된다
- [ ] 취소 불가 사유(마감 시각 경과 / 이미 완료 / 이미 취소 / 노쇼)가 구분돼 표시된다
- [ ] 취소 실행 전에 전체 취소임을 확인받는다

**예외**
- 없음

- [ ] 최근 30일 노쇼 횟수와 주문 제한 여부가 확인된다
- [ ] 노쇼 3회 누적으로 제한된 상태에서는 주문 제한 해제 예정 시각이 표시된다
- [ ] 노쇼 주문의 수량은 잔여 수량으로 복구되지 않는다

**예외**
- 없음

### FR-032 · 주문 제한 상태 안내

### FR-042 · 상품 판매 상태 전환

- 사용자: 관리자
- 관련 규칙: BR-030
- 우선순위: 필수

**설명**
상품을 판매 중, 숨김, 판매 종료 상태로 바꾼다.

**완료 조건**
- [ ] DRAFT 또는 HIDDEN 상태의 상품을 ON_SALE로 바꾸면 고객 목록에 즉시 노출된다
- [ ] ON_SALE 상품을 HIDDEN으로 바꾸면 목록·검색·상세에서 즉시 빠진다
- [ ] HIDDEN 전환은 기존 PENDING 선점과 CONFIRMED 주문을 취소하지 않는다
- [ ] HIDDEN 전환 이후 신규 주문서 생성이 차단된다
- [ ] CLOSED로 바뀐 상품은 다시 ON_SALE로 되돌릴 수 없다
- [ ] 재고가 등록되지 않은 상품은 ON_SALE로 바꿀 수 없다

**예외**
- 마감 시각이 지나면 관리자 조작 없이 CLOSED로 전환된다

### FR-043 · 마감 시각 설정

### 3.2 재고 관리

### FR-045 · 재고 등록 및 조정

- 사용자: 관리자
- 관련 규칙: BR-006, BR-025
- 우선순위: 필수

**설명**
상품의 총 재고 수량을 등록하고 조정한다.

**완료 조건**
- [ ] 상품의 총 재고 수량을 0 이상 정수로 등록한다
- [ ] 총 재고를 늘리면 판매 가능 수량이 같은 만큼 늘어난다
- [ ] 총 재고를 (선점 중 수량 + 확정 판매 수량) 미만으로 줄이려 하면 거부되고 최소 가능 값을 알린다
- [ ] 재고 축소로 이미 만들어진 선점이나 확정 주문이 취소되지 않는다
- [ ] 재고 변경 시각, 변경 전후 수량, 변경자가 이력으로 남는다

**예외**
- 음수나 소수 수량은 저장하지 않는다

### FR-046 · 재고 현황 조회

- 사용자: 관리자
- 관련 규칙: BR-006
- 우선순위: 필수

**설명**
상품별 재고 구성을 나눠서 본다.

**완료 조건**
- [ ] 상품마다 총 재고, 판매 가능, 선점 중, 확정 판매 수량이 각각 표시된다
- [ ] 총 재고 = 판매 가능 + 선점 중 + 확정 판매가 항상 성립한다
- [ ] 선점 중 수량에는 만료된 선점이 포함되지 않는다
- [ ] 판매 가능 수량이 0인 상품을 걸러 볼 수 있다

**예외**
- 없음

### FR-047 · 재고 변경 이력 조회

- 사용자: 관리자
- 관련 규칙: BR-006, BR-019, BR-022
- 우선순위: 선택

**설명**
재고 수량이 언제 왜 변했는지 추적한다. 노쇼는 재고 수량을 바꾸지 않으므로(BR-022) 이 이력의 추적 대상이 아니다.

**완료 조건**
- [ ] 변경 사유(관리자 조정 / 선점 / 선점 해제 / 선점 만료 / 확정 차감 / 취소 복구 / 취소 폐기)가 구분돼 표시된다
- [ ] 각 이력에 시각, 변경 수량, 관련 주문 번호가 표시된다
- [ ] 이력은 수정하거나 삭제할 수 없다
- [ ] 노쇼로 전환된 주문은 재고 수량을 바꾸지 않으므로 이 이력에 나타나지 않는다

**예외**
- 노쇼 판정 시각과 결과는 이 이력이 아니라 주문 상세(FR-031)와 노쇼 목록(FR-053)에서 확인한다

### FR-051 · 픽업 준비 완료 처리

- 사용자: 관리자
- 관련 규칙: BR-020
- 우선순위: 선택

**완료 조건**

- [ ] READY 전환은 재고 수량을 바꾸지 않는다

### FR-052 · 픽업 완료 처리

- 사용자: 관리자
- 관련 규칙: BR-020, BR-021
- 우선순위: 필수

**설명**
고객이 상품을 수령하면 주문을 완료로 처리한다.

**완료 조건**
- [ ] CONFIRMED 또는 READY 주문을 COMPLETED로 바꿀 수 있다
- [ ] 완료 처리 시각이 기록된다
- [ ] COMPLETED 전환은 재고 수량을 바꾸지 않는다
- [ ] COMPLETED 주문은 취소·노쇼·준비 완료 등 다른 상태로 바꿀 수 없다
- [ ] 같은 주문을 두 번 완료 처리할 수 없다
- [ ] 노쇼 유예 시간이 끝나기 전이면 픽업 시간대가 지난 주문도 완료 처리할 수 있다

**예외**
- 이미 NO_SHOW로 전환된 주문은 완료 처리할 수 없다

### FR-053 · 노쇼 처리 결과 확인

- 사용자: 관리자
- 관련 규칙: BR-021, BR-022
- 우선순위: 필수

**완료 조건**

- [ ] 노쇼 전환에는 관리자 조작이 필요하지 않다
- [ ] 노쇼 목록에서 주문 번호, 픽업 시간대, 노쇼 판정 시각을 확인한다
- [ ] 노쇼 전환 시 재고가 복구되지 않는다
- [ ] 이미 NO_SHOW인 주문을 다시 노쇼 처리해도 상태와 이력이 중복 생성되지 않는다

**예외**
- 없음

### FR-054 · 관리자 주문 취소

- 사용자: 관리자
- 관련 규칙: BR-019, BR-020, BR-024
- 우선순위: 필수

**설명**
운영 사유로 확정된 주문을 관리자가 취소한다.

**완료 조건**
- [ ] CONFIRMED 또는 READY 주문을 고객 취소 마감 시각과 무관하게 취소할 수 있다
- [ ] 취소 사유를 입력하지 않으면 취소가 실행되지 않는다
- [ ] 취소 시 상품 마감 시각이 지나지 않았으면 재고가 복구된다
- [ ] 취소 시 상품 마감 시각이 지났으면 재고가 복구되지 않고 그 사실이 이력에 남는다
- [ ] 취소 시 해당 픽업 시간대 정원 1건이 반납된다
- [ ] COMPLETED, NO_SHOW, CANCELED 주문은 취소할 수 없다
- [ ] 취소 사유가 고객 주문 상세에 표시된다

**예외**
- 부분 취소는 지원하지 않는다
