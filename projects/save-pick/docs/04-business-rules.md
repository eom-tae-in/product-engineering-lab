## 1. 기본

### BR-001 · 단일 매장 운영

- 규칙: 서비스가 다루는 매장은 1곳이며 모든 상품·재고·픽업은 이 매장에 속한다.
- 적용 대상: 상품, 재고, 픽업 시간대, 주문 전체
- 위반 시 처리: 매장 구분이 필요한 요청은 처리하지 않는다.
- 근거: 첫 버전 전제. 매장 개념을 데이터에 도입하면 재고·픽업 규칙 전체가 바뀐다.
- 관련 요구사항: FR-033

### BR-002 · 계정과 권한

- 규칙: 계정 권한은 `고객`과 `관리자` 둘뿐이다. 주문 생성·조회·취소는 본인 주문에 한정하고, 관리자 기능은 관리자 권한만 사용한다.
- 적용 대상: 모든 인증·인가 판단
- 위반 시 처리: 권한 없는 요청은 거부하고 어떤 데이터도 반환하지 않는다.
- 근거: 단일 매장 운영이며 관리자는 소수다. 권한을 더 나누면 운영 부담만 늘어난다.
- 관련 요구사항: FR-001, FR-002, FR-003, FR-004, FR-027, FR-048, FR-050

### BR-028 · 시각 판정 기준

- 규칙: 할인 구간, 선점 만료, 픽업 예약 마감, 취소 마감, 노쇼 판정은 모두 서버 시각(KST, UTC+9)으로 판단한다.
- 적용 대상: 시간이 개입하는 모든 판정
- 위반 시 처리: 고객 기기 시각과 서버 시각이 달라도 서버 시각을 따른다. 화면 표시와 서버 판정이 어긋나면 서버 판정 결과를 알린다.
- 근거: 기기 시각을 신뢰하면 선점 만료와 취소 마감을 우회할 수 있다.
- 관련 요구사항: FR-005, FR-020, FR-029

## 2. 할인

### BR-003 · 상품 마감 시각의 정의

- 규칙: 마감 시각은 관리자가 상품별로 분 단위로 지정하는 **판매 종료 시각**이다. 이 시각이 할인 구간 계산과 판매 종료 판정의 유일한 기준이다.
- 적용 대상: 모든 상품
- 위반 시 처리: 마감 시각이 현재보다 과거이거나 영업 종료 시각(22:00)을 넘으면 저장하지 않는다.
- 근거: 신선식품마다 소비 기한이 달라 상품별 마감 시각이 필요하다. 기준이 하나여야 할인과 판매 종료가 어긋나지 않는다.
- 관련 요구사항: FR-014, FR-040, FR-041, FR-043

### BR-004 · 마감 할인율 구간과 적용 시점

- 규칙: 할인율은 **조회 시점의 서버 시각과 상품 마감 시각의 차이**로 자동 결정한다. 관리자가 개별 상품의 할인율을 수동 지정하지 않는다.

| 구간 | 마감까지 남은 시간 | 할인율 |
|---|---|---|
| D0 | 24시간 초과 | 0% (정가) |
| D1 | 24시간 이하 ~ 6시간 초과 | 30% |
| D2 | 6시간 이하 ~ 2시간 초과 | 50% |
| D3 | 2시간 이하 ~ 마감 시각 이전 | 70% |
| — | 마감 시각 도달 이후 | 판매 종료 (BR-030) |

  - 할인가 = `내림(정가 × (1 − 할인율) ÷ 10) × 10` (10원 단위 내림)
  - 계산 결과가 100원 미만이면 100원으로 한다.
  - 구간 경계값은 더 큰 할인율 구간에 속한다. (남은 시간이 정확히 6시간이면 D2를 적용한다)
- 적용 대상: 상품 목록·검색·상세 조회, 장바구니 금액 재계산, 주문서 생성
- 위반 시 처리: 구간 계산이 불가능하면(마감 시각 미설정) 상품을 ON_SALE로 전환하지 않는다.
- 근거: 남은 시간이 짧을수록 폐기 위험이 커지므로 할인 폭을 키워 소진을 유도한다. 자동 계산이라야 관리자가 상품마다 가격을 조정하지 않아도 된다.
- 관련 요구사항: FR-010, FR-012, FR-013, FR-014, FR-043, FR-044

### BR-005 · 판매 금액 확정 시점

- 규칙: 결제 금액은 **주문서 생성 시점**의 할인가로 고정된다. 주문서 생성 이후 할인 구간이 바뀌거나 관리자가 정가를 바꿔도 해당 주문의 금액은 변하지 않는다.
- 적용 대상: 주문서 생성 ~ 결제 완료
- 위반 시 처리: 결제 요청 금액이 주문서 확정 금액과 다르면 결제를 진행하지 않는다.
- 근거: 선점 유효 시간(10분) 안에 할인 구간이 바뀌면 고객이 본 금액과 결제 금액이 달라진다.
- 관련 요구사항: FR-018, FR-021, FR-041

### BR-030 · 마감 시각 도달 시 판매 종료

- 규칙: 상품의 마감 시각에 도달하면 상품 상태를 CLOSED로 전환하고 신규 노출·담기·주문서 생성을 모두 차단한다. 이미 만들어진 PENDING 선점은 그 선점의 만료 시각까지 유효하며 그 안에 결제하면 주문이 확정된다.
- 적용 대상: 모든 상품
- 위반 시 처리: 마감 이후 담기·주문 시도는 거부하고 판매 종료를 알린다.
- 근거: 마감 시각은 판매 종료 기준이지만, 이미 선점하고 결제 중인 고객의 거래까지 끊으면 결제 흐름이 깨진다.
- 관련 요구사항: FR-010, FR-011, FR-013, FR-034, FR-042

## 3. 재고

### BR-006 · 재고 구성과 잔여 수량 산정

- 규칙: 상품 재고는 아래 네 값으로 관리한다.

| 값 | 정의 |
|---|---|
| 총 재고 | 관리자가 등록한 실물 수량 |
| 선점 중 | 유효한 PENDING 주문서가 잡고 있는 수량 |
| 확정 판매 | CONFIRMED·READY·COMPLETED·NO_SHOW 주문의 수량 |
| 판매 가능(잔여 수량) | 총 재고 − 선점 중 − 확정 판매 |

  - 고객에게 표시하는 잔여 수량은 `판매 가능` 값이다.
  - 판매 가능 값은 항상 0 이상이다.
- 적용 대상: 상품 목록·상세, 재고 현황
- 위반 시 처리: 판매 가능 값이 음수가 되는 연산은 실행하지 않고 거부한다.
- 근거: 선점 수량과 확정 수량을 분리해야 초과 판매를 막고 재고 이동을 추적할 수 있다.
- 관련 요구사항: FR-010, FR-013, FR-015, FR-045, FR-046, FR-047

### BR-007 · 재고 임시 선점의 유효 시간

- 규칙: 선점은 주문서 생성 시점부터 **10분간** 유효하다. 연장은 없다.
- 적용 대상: 주문서 생성 ~ 결제 완료 사이
- 위반 시 처리: 유효 시간이 지나면 선점을 해제하고 판매 가능 재고로 복구한다. 고객에게는 만료를 알리고 주문을 다시 시작하게 한다.
- 근거: 재고가 무한정 묶이면 다른 고객의 구매가 막힌다. 결제 수단 확인과 픽업 시간대 선택에 필요한 시간을 고려해 10분으로 정한다.
- 관련 요구사항: FR-019, FR-020, FR-025

### BR-008 · 선점 만료 처리

- 규칙: 만료 판정은 결제 요청 시점과 주기적 정리 두 경로 모두에서 이뤄지며, 정리 주기는 **1분**을 넘지 않는다. 만료된 선점은 즉시 해제되고 주문은 EXPIRED가 된다.
- 적용 대상: PENDING 주문과 그에 연결된 선점
- 위반 시 처리: 만료된 선점으로 결제를 시도하면 결제를 진행하지 않고 만료를 알린다. EXPIRED에서 PENDING으로 되돌리지 않는다.
- 근거: 정리 주기가 길면 실제로는 비어 있는 재고가 오래 잠긴 것처럼 보인다.
- 관련 요구사항: FR-015, FR-019, FR-020

### BR-009 · 1회 주문 수량 한도

- 규칙: 상품별 1회 주문 최대 수량은 관리자가 지정하며 기본값은 **5개**다. 하나의 주문에는 최대 **10개 품목**을 담는다.
- 적용 대상: 장바구니 담기, 수량 변경, 주문서 생성
- 위반 시 처리: 한도를 넘는 수량은 담기지 않고 한도를 알린다.
- 근거: 한 고객이 마감 할인 재고를 독점하면 다른 고객의 구매 기회와 매장 신뢰가 함께 손상된다.
- 관련 요구사항: FR-013, FR-016, FR-017, FR-040

### BR-010 · 장바구니는 재고를 선점하지 않는다

- 규칙: 장바구니에 담는 행위는 재고에 영향을 주지 않는다. 선점은 주문서 생성 시점에만 발생한다.
- 적용 대상: 장바구니 전 기능
- 위반 시 처리: 담긴 수량이 주문서 생성 시점에 부족하면 부족 수량을 알리고 주문서를 만들지 않는다.
- 근거: 담고 이탈하는 비율이 높아 담기 시점에 선점하면 재고가 과도하게 묶인다.
- 관련 요구사항: FR-016, FR-018, FR-019

### BR-025 · 관리자 재고 축소와 선점의 충돌 처리

- 규칙: 총 재고는 `선점 중 + 확정 판매` 미만으로 줄일 수 없다. 이미 만들어진 선점과 확정 주문은 재고 축소로 취소되지 않는다.
- 적용 대상: 관리자 재고 조정
- 위반 시 처리: 축소 요청을 거부하고 설정 가능한 최소값을 알린다. 즉시 판매를 멈춰야 하면 상품 상태를 HIDDEN으로 바꿔 신규 주문만 차단한다.
- 근거: 이미 결제한 고객의 주문을 관리자 조작으로 무효화하면 신뢰가 깨진다.
- 관련 요구사항: FR-042, FR-045, FR-046

### BR-027 · 재고 경합 처리

- 규칙: 같은 상품의 잔여 수량을 여러 고객이 동시에 요청하면 먼저 처리된 요청만 선점에 성공한다. 하나의 주문서는 전 품목이 모두 선점 가능할 때만 생성되며 **부분 선점은 만들지 않는다**.
- 적용 대상: 주문서 생성
- 위반 시 처리: 한 품목이라도 부족하면 어떤 품목도 선점하지 않고 부족 품목과 수량을 알린다.
- 근거: 부분 선점을 허용하면 고객이 의도하지 않은 수량으로 결제하게 되고, 남은 선점이 다른 고객의 재고를 묶는다.
- 관련 요구사항: FR-019

## 4. 결제

### BR-011 · 가상 결제의 성공·실패 판정

- 규칙: 결제는 실제 금전 이동 없이 **성공 또는 실패** 결과만 반환한다. 성공 시 주문을 확정하고, 실패 시 BR-012를 따른다. 결제 결과는 주문 이력으로 남긴다.
- 적용 대상: 모든 결제 요청
- 위반 시 처리: 성공·실패 외의 응답이나 무응답은 실패로 간주한다.
- 근거: 첫 버전 전제. 실제 결제 연동은 제외 범위다.
- 관련 요구사항: FR-024, FR-025

### BR-012 · 결제 실패 시 선점 재고 처리

- 규칙:
  1. 결제 1회 실패로는 선점을 해제하지 않는다. 남은 선점 유효 시간 동안 재시도할 수 있다.
  2. 같은 주문서의 결제 시도 한도는 **3회**다.
  3. 3회째 실패하면 주문을 FAILED로 바꾸고 선점을 **즉시 해제**해 판매 가능 재고로 복구한다.
  4. 재시도 횟수가 남아 있어도 선점 유효 시간(10분)이 끝나면 결제할 수 없고 주문은 EXPIRED가 된다.
  5. 즉, 재고 복구 시점은 `3회째 실패`와 `선점 만료` 중 **먼저 오는 시점**이다.
- 적용 대상: PENDING 주문의 결제
- 위반 시 처리: FAILED 또는 EXPIRED 주문으로 결제를 시도하면 거부하고 새 주문서를 만들게 한다.
- 근거: 카드 오입력 같은 단순 실패로 매번 재고를 놓치면 구매가 어려워진다. 반대로 무제한 재시도를 허용하면 재고가 계속 묶인다.
- 관련 요구사항: FR-024, FR-025

### BR-029 · 표시 금액과 결제 금액의 일치

- 규칙: 결제 요청 금액은 주문서에 확정된 합계 금액과 정확히 같아야 한다.
- 적용 대상: 결제 요청
- 위반 시 처리: 금액이 다르면 결제를 진행하지 않고 주문서를 다시 확인하게 한다.
- 근거: 클라이언트가 보낸 금액을 그대로 받으면 실제 판매가와 다른 금액으로 확정될 수 있다.
- 관련 요구사항: FR-021, FR-024

## 5. 픽업

### BR-013 · 픽업 가능 날짜 범위

- 규칙: 픽업 날짜는 **오늘(D+0)과 내일(D+1)** 중에서만 선택한다. D+2 이후는 선택할 수 없다.
- 적용 대상: 픽업 날짜 선택
- 위반 시 처리: 범위 밖 날짜 요청은 거부한다.
- 근거: 마감 임박 신선식품은 최대 24시간 안에 소비돼야 한다. 범위를 넓히면 상품 마감 시각과 충돌한다.
- 관련 요구사항: FR-022

### BR-014 · 픽업 시간대 단위와 영업시간

- 규칙: 픽업 시간대는 영업시간 안에서 **30분 단위**로 나눈다. 기본 영업시간은 **10:00~22:00**이며 첫 시간대는 10:00~10:30, 마지막 시간대는 21:30~22:00이다. 하루 24개 시간대가 생성된다. 영업시간은 관리자가 30분 단위로 조정한다.
- 적용 대상: 픽업 시간대 생성과 노출
- 위반 시 처리: 영업시간 밖 시간대는 생성하지 않고 선택할 수 없다.
- 근거: 30분 단위는 매장이 준비할 수 있는 최소 단위이면서 고객이 도착 시간을 맞추기 부담스럽지 않은 폭이다.
- 관련 요구사항: FR-023, FR-055, FR-056

### BR-015 · 픽업 시간대 예약 마감 시각

- 규칙: 각 시간대의 예약 마감 시각은 **시간대 시작 30분 전**이다. 현재 시각이 마감 시각을 지난 시간대는 선택할 수 없다. (예: 20:00~20:30 시간대는 19:30까지 예약 가능)
- 적용 대상: 픽업 시간대 선택, 결제 완료 시점 검증
- 위반 시 처리: 마감된 시간대로 결제를 시도하면 결제를 진행하지 않고 시간대를 다시 고르게 한다.
- 근거: 매장이 상품을 담아 두려면 최소한의 준비 시간이 필요하다.
- 관련 요구사항: FR-022, FR-023

### BR-016 · 픽업 시간대 정원

- 규칙: 한 시간대에 받을 수 있는 확정 주문은 기본 **20건**이다. 정원은 관리자가 1 이상 정수로 조정하며, 변경은 이후 생성되는 주문부터 적용된다. 관리자는 특정 시간대를 개별 차단할 수 있다.
  - 정원 소진 판정 대상은 CONFIRMED, READY, COMPLETED 주문이다.
  - CANCELED, NO_SHOW, EXPIRED, FAILED 주문은 정원을 점유하지 않는다. 단 NO_SHOW는 픽업 시각이 이미 지난 뒤 발생하므로 정원 반납이 실질적 의미를 갖지 않는다.
- 적용 대상: 픽업 시간대 선택, 주문 확정
- 위반 시 처리: 정원이 찬 시간대는 선택 목록에서 제외한다. 결제 직전 정원이 찼으면 결제를 진행하지 않고 다른 시간대를 고르게 한다.
- 근거: 한 시간대에 고객이 몰리면 대기가 생기고 상품 준비가 늦어진다. 30분에 20건은 1.5분당 1건 응대 수준이다.
- 관련 요구사항: FR-023, FR-055, FR-057, FR-058

### BR-017 · 픽업 시간대와 상품 마감 시각의 관계

- 규칙: 선택 가능한 픽업 시간대는 **주문 품목 중 가장 이른 마감 시각보다 늦게 시작하지 않는** 시간대로 한정한다.
- 적용 대상: 픽업 시간대 선택
- 위반 시 처리: 조건에 맞는 시간대가 없으면 주문을 진행할 수 없고 사유를 알린다.
- 근거: 마감 시각을 넘긴 상품은 판매·수령 대상이 아니다. 마감 이후 픽업을 허용하면 상품 품질을 보장할 수 없다.
- 관련 요구사항: FR-022, FR-023

## 6. 취소와 노쇼

### BR-018 · 고객 주문 취소 가능 시점

- 규칙: 고객은 **픽업 시간대 시작 시각의 1시간 전까지** 확정 주문을 직접 취소할 수 있다. 그 이후에는 고객이 취소할 수 없다.
  - 취소 가능 상태는 CONFIRMED와 READY다.
  - 취소 가능 마감 시각은 주문 확정 시점에 계산해 고객에게 표시한다.
- 적용 대상: 고객 취소
- 위반 시 처리: 마감 시각이 지난 취소 요청은 거부하고 사유와 기준 시각을 알린다. 필요하면 관리자 취소(BR-020)로 처리한다.
- 근거: 매장이 준비를 시작하기 전에 취소돼야 재고를 다시 팔 수 있다. 1시간이면 상품을 다시 진열하고 판매할 여지가 남는다.
- 관련 요구사항: FR-028, FR-029, FR-030

### BR-019 · 취소 시 재고 복구 규칙

- 규칙: 취소 시 재고 복구 여부는 **취소 실행 시점**과 **상품 마감 시각**의 관계로 결정한다.

| 취소 실행 시점 | 재고 복구 | 결과 |
|---|---|---|
| 상품 마감 시각 이전 | 복구한다 | 취소 수량이 즉시 판매 가능 재고로 돌아가고 다른 고객이 바로 구매할 수 있다 |
| 상품 마감 시각 이후 | 복구하지 않는다 | 총 재고에서 폐기 수량으로 분류하고 복구 불가 사유를 이력에 남긴다 |

  - 픽업 시간대 정원은 취소 시점과 무관하게 항상 1건 반납한다.
  - 여러 품목 중 일부만 마감 시각이 지난 경우, 마감 전 품목만 복구한다.
- 적용 대상: 고객 취소, 관리자 취소
- 위반 시 처리: 마감 이후 복구를 시도하면 실행하지 않고 폐기로 기록한다.
- 근거: 마감 시각이 지난 상품을 재고로 되살리면 팔 수 없는 수량이 판매 가능으로 표시된다.
- 관련 요구사항: FR-029, FR-047, FR-054

### BR-020 · 관리자 취소 권한

- 규칙: 관리자는 CONFIRMED와 READY 주문을 고객 취소 마감 시각과 무관하게 취소할 수 있다. **취소 사유 입력은 필수**다. COMPLETED, NO_SHOW, CANCELED 주문은 취소할 수 없다.
- 적용 대상: 관리자 취소
- 위반 시 처리: 사유가 없으면 취소를 실행하지 않는다. 취소 불가 상태에 대한 요청은 거부한다.
- 근거: 상품 이상이나 매장 사정으로 이행할 수 없는 주문이 생긴다. 사유를 남겨야 고객 문의에 답할 수 있다.
- 관련 요구사항: FR-051, FR-052, FR-054

### BR-024 · 부분 취소 불가

- 규칙: 취소는 항상 주문 단위이며 일부 품목이나 일부 수량만 취소할 수 없다.
- 적용 대상: 고객 취소, 관리자 취소
- 위반 시 처리: 부분 취소 요청은 거부한다.
- 근거: 가상 결제에는 부분 환불 개념이 없다. 부분 취소를 허용하면 결제 금액과 주문 내용이 어긋난다.
- 관련 요구사항: FR-029, FR-054

### BR-021 · 노쇼 판정 기준

- 규칙: 픽업 시간대 종료 시각으로부터 **30분의 유예**를 둔다. 유예가 끝난 시점에도 CONFIRMED 또는 READY 상태인 주문은 자동으로 NO_SHOW가 된다.
  - 예: 20:00~20:30 픽업 주문은 21:00에 노쇼로 전환된다.
  - 유예 시간 안에 고객이 방문하면 정상 픽업(COMPLETED)으로 처리한다.
  - 자동 전환 검사 주기는 5분을 넘지 않는다.
- 적용 대상: 확정된 모든 주문
- 위반 시 처리: NO_SHOW에서 다른 상태로 되돌리지 않는다.
- 근거: 30분 지각은 실제 매장에서 흔하다. 유예 없이 판정하면 정상 고객이 노쇼로 처리된다.
- 관련 요구사항: FR-031, FR-052, FR-053

### BR-022 · 노쇼 처리 결과

- 규칙: 노쇼 주문은 아래와 같이 처리한다.

| 항목 | 처리 |
|---|---|
| 결제 금액 | 환불하지 않는다 (가상 결제이므로 금전 이동 없이 미환불로 기록한다) |
| 재고 | 판매 가능 재고로 복구하지 않는다 |
| 상품 실물 | 매장이 폐기한다 (서비스 밖 행위) |
| 픽업 번호 | 무효 처리하고 이후 수령할 수 없다 |
| 이력 | 노쇼 판정 시각을 기록한다 |

- 적용 대상: NO_SHOW 주문
- 위반 시 처리: 노쇼 주문의 재고를 복구하려는 요청은 거부한다.
- 근거: 노쇼는 픽업 시간대와 마감 시각이 모두 지난 뒤 발생하므로 되팔 수 없다. 미환불은 반복 노쇼를 억제한다.
- 관련 요구사항: FR-031, FR-053

### BR-023 · 노쇼 누적 제재

- 규칙: 최근 **30일** 동안 노쇼가 **3회** 누적된 계정은 이후 **7일간** 새 주문서를 만들 수 없다.
  - 판정 기준일은 노쇼 판정 시각이다.
  - 제한 기간에도 로그인, 상품 조회, 장바구니 담기, 기존 주문 조회는 가능하다.
  - 이미 확정된 주문은 제한으로 취소되지 않는다.
  - 제한 기간이 끝나면 별도 절차 없이 주문할 수 있다.
- 적용 대상: 고객 계정
- 위반 시 처리: 제한 상태에서 주문서 생성을 시도하면 거부하고 해제 예정 시각을 알린다.
- 근거: 노쇼 1건은 상품 1건의 폐기와 같다. 반복 노쇼를 막지 않으면 매장 손실이 누적된다.
- 관련 요구사항: FR-019, FR-031, FR-032

## 7. 운영

### BR-026 · 주문 번호와 픽업 번호 발급

- 규칙: 주문 확정 시 두 식별자를 발급한다.

| 식별자 | 용도 | 규칙 |
|---|---|---|
| 주문 번호 | 주문 조회·문의 | 서비스 전체에서 유일하며 재사용하지 않는다 |
| 픽업 번호 | 매장 응대 | 같은 영업일 안에서만 유일한 3자리 순번 |

  - 픽업 번호는 CONFIRMED 도달 시에만 발급하며 PENDING, EXPIRED, FAILED 주문에는 발급하지 않는다.
  - 취소·노쇼된 주문의 픽업 번호는 같은 영업일 안에서 재사용하지 않는다.
- 적용 대상: 주문 확정
- 위반 시 처리: 같은 영업일에 픽업 번호가 중복 발급되면 확정을 완료하지 않고 다시 발급한다.
- 근거: 매장에서 구두로 부르기 쉬운 짧은 번호가 필요하지만, 조회·추적에는 전역 유일 번호가 필요하다.
- 관련 요구사항: FR-026, FR-028, FR-049

## 8. 규칙 간 우선순위

규칙이 충돌할 때 아래 순서로 판단한다.

| 순위 | 원칙 | 적용 예 |
|---|---|---|
| 1 | 초과 판매를 만들지 않는다 | 총 재고보다 많은 확정 수량은 어떤 경우에도 허용하지 않는다 (BR-006, BR-027) |
| 2 | 이미 확정된 주문을 지킨다 | 관리자 재고 축소나 영업시간 변경이 확정 주문을 취소하지 못한다 (BR-025, BR-014) |
| 3 | 팔 수 없는 재고를 판매 가능으로 표시하지 않는다 | 마감 이후 취소분은 복구하지 않는다 (BR-019) |
| 4 | 고객이 본 금액과 결제 금액이 같다 | 할인 구간이 바뀌어도 확정 금액을 유지한다 (BR-005, BR-029) |
| 5 | 재고를 오래 묶지 않는다 | 선점 10분, 재시도 3회로 제한한다 (BR-007, BR-012) |

### 가정 (확인 필요)

| # | 가정한 내용 | 근거 | 틀릴 경우 영향 |
|---|---|---|---|
| A1 | 할인 구간을 24h/6h/2h 기준 0%·30%·50%·70% 4단계로 정한다 | 마감이 가까울수록 폐기 위험이 커지므로 단계적으로 폭을 키운다. 3단계는 변화가 둔하고 5단계 이상은 관리자가 이해하기 어렵다 | 할인율만 바꾸면 되며 기능 구조에는 영향이 없다 |
| A2 | 할인가는 10원 단위 내림, 최저 100원으로 한다 | 표시 가격을 단순하게 하고 0원 판매를 막는다 | 금액 계산식과 표시 규칙이 바뀐다 |
| A3 | 선점 유효 시간을 10분으로 정한다 | 픽업 시간대 선택과 결제 확인에 필요한 시간을 고려. 5분은 시간대 비교에 부족하고 15분은 재고가 오래 묶인다 | 주문 흐름의 시간 제약과 동시성 설계가 바뀐다 |
