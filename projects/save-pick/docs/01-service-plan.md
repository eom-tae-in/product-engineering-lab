## 한 줄 요약
마감이 임박한 신선식품을 할인가로 판매하고, 고객이 직접 고른 시간에 매장에서 픽업하도록 연결하는 서비스의 목적·대상·가치·성공 지표를 정의한다.

---

## 1. 서비스 정의

savePick은 단일 매장이 보유한 **마감 임박 신선식품**을 마감 시각까지 남은 시간에 따라 자동 할인해 판매하고, 고객이 원하는 픽업 시간대를 선택해 매장에서 직접 수령하도록 연결하는 온라인 주문·픽업 서비스다.

첫 버전은 다음 전제 위에서 만든다.

| 전제 | 내용 |
|---|---|
| 매장 범위 | 단일 매장 1곳 |
| 수령 방식 | 고객이 매장을 방문해 직접 픽업 |
| 결제 | 성공·실패 결과만 확인 가능한 가상 결제 |
| 재고 | 매장 실물 재고를 관리자가 직접 등록·조정 |

## 2. 해결하려는 문제

| # | 문제 | 현재 상황 | savePick의 해결 |
|---|---|---|---|
| P1 | 매장의 마감 폐기 손실 | 마감 시각까지 팔리지 않은 신선식품은 전량 폐기된다 | 남은 시간에 따라 자동으로 할인해 판매 기회를 늘린다 |
| P2 | 할인 정보의 비대칭 | 고객은 매장에 직접 가야 마감 할인 여부를 안다 | 온라인에서 현재 할인가와 잔여 수량을 확인한다 |
| P3 | 헛걸음 | 매장 도착 시 이미 품절인 경우가 있다 | 주문 시 재고를 확정해 수령을 보장한다 |
| P4 | 픽업 시각 혼잡 | 마감 직전 고객이 몰려 응대가 어렵다 | 픽업 시간대를 나눠 예약받아 분산한다 |

## 3. 대상 사용자

### 3.1 고객

| 구분 | 내용 |
|---|---|
| 정의 | 매장 도보·차량 이동권 안에 거주하거나 근무하며 직접 매장을 방문할 수 있는 일반 소비자 |
| 핵심 동기 | 신선식품을 정가보다 싸게 사는 것 |
| 사용 맥락 | 퇴근 전후, 장보기 직전에 짧게 확인하고 바로 주문한다 |
| 성공 경험 | 원하는 상품을 할인가로 확보하고, 지정한 시간에 기다리지 않고 받아 간다 |

### 3.2 관리자

| 구분 | 내용 |
|---|---|
| 정의 | 매장 운영자 또는 매장 직원 |
| 핵심 동기 | 폐기 손실을 줄이고, 픽업 응대 부담을 예측 가능하게 만드는 것 |
| 사용 맥락 | 개점 시 상품·재고를 등록하고, 영업 중 주문과 픽업 현황을 확인한다 |
| 성공 경험 | 마감 전에 재고를 소진하고, 시간대별 픽업 건수를 미리 안다 |

## 4. 가치 제안

### 4.1 고객에게

| # | 가치 | 근거가 되는 기능 범위 |
|---|---|---|
| V1 | 지금 이 매장에서 가장 싼 신선식품을 안다 | 마감 할인가·잔여 수량 표시 |
| V2 | 사러 갔는데 없는 일이 없다 | 주문 중 재고 임시 선점, 주문 확정 시 수량 확보 |
| V3 | 내 일정에 맞춰 받는다 | 픽업 날짜·시간대 선택 |
| V4 | 계획이 바뀌면 되돌릴 수 있다 | 주문 취소와 재고 복구 |

### 4.2 관리자에게

| # | 가치 | 근거가 되는 기능 범위 |
|---|---|---|
| V5 | 폐기 직전 재고를 매출로 바꾼다 | 시간 기반 자동 할인 |
| V6 | 재고를 한 곳에서 관리한다 | 관리자 상품·재고 관리 |
| V7 | 오늘 몇 시에 몇 건을 준비할지 미리 안다 | 시간대별 픽업 현황 조회 |
| V8 | 준비·수령·노쇼를 기록으로 남긴다 | 관리자 주문 관리 |

## 5. MVP 범위

### 5.1 포함

| 영역 | 포함 내용 |
|---|---|
| 계정 | 회원가입, 로그인 |
| 상품 | 목록, 상세, 검색 |
| 가격·재고 | 마감 할인가 표시, 잔여 수량 표시 |
| 구매 | 장바구니, 주문, 주문 중 재고 임시 선점 |
| 픽업 | 픽업 날짜·시간 선택 |
| 사후 | 주문 취소, 재고 복구 |
| 운영 | 관리자 상품·재고·주문 관리 |
| 결제 | 성공·실패만 판정하는 가상 결제 |

### 5.2 제외

아래 항목은 첫 버전에서 **만들지 않으며, 기능 요구사항으로도 쓰지 않는다.**

| 제외 항목 | 이유 |
|---|---|
| 실제 결제 연동 | 결제는 성공·실패 판정만으로 흐름을 검증한다 |
| 실시간 배송·라이더 배정 | 수령 방식은 매장 픽업 하나로 고정한다 |
| 지도·위치 추적 | 단일 매장이므로 위치 탐색이 필요 없다 |
| AI 추천 | 상품 수가 적고 마감 임박 여부가 곧 우선순위다 |
| 다중 매장 재고 연동 | 첫 버전은 단일 매장 전제다 |

## 6. 성공 지표

측정 기간은 서비스 공개 후 첫 8주로 한다.

### 6.1 핵심 지표

| # | 지표 | 정의 | 목표 |
|---|---|---|---|
| M1 | 마감 소진율 | (마감 할인 대상 상품 중 픽업 완료 수량) ÷ (마감 할인 대상 등록 수량) | 60% 이상 |
| M2 | 주문 전환율 | (주문 확정 건수) ÷ (상품 상세 조회 세션 수) | 8% 이상 |
| M3 | 픽업 완료율 | (COMPLETED 주문 건수) ÷ (CONFIRMED 도달 주문 건수) | 90% 이상 |
| M4 | 노쇼율 | (NO_SHOW 주문 건수) ÷ (CONFIRMED 도달 주문 건수) | 5% 이하 |

### 6.2 보조 지표

| # | 지표 | 정의 | 목표 |
|---|---|---|---|
| M5 | 선점 만료율 | (선점 만료로 종료된 주문서 수) ÷ (생성된 주문서 수) | 15% 이하 |
| M6 | 결제 실패 후 재시도 성공률 | (재시도로 확정된 주문 수) ÷ (1회 이상 결제 실패한 주문 수) | 70% 이상 |
| M7 | 고객 취소율 | (고객 취소 건수) ÷ (CONFIRMED 도달 주문 건수) | 10% 이하 |
| M8 | 재구매율 | 8주 내 2회 이상 픽업 완료한 고객 비율 | 30% 이상 |
| M9 | 픽업 시간대 분산도 | 하루 최대 슬롯 예약 건수 ÷ 하루 평균 슬롯 예약 건수 | 3.0 이하 |

### 6.3 지표 판정 규칙

- 모든 지표는 매장 영업일 기준으로 집계한다.
- M1은 관리자가 마감 할인 대상으로 등록한 상품만 모수로 삼는다.
- M3, M4, M7의 모수는 동일하며 세 지표의 합은 100%를 넘지 않는다.

## 7. 범위 밖 판단 기준

새 아이디어가 나왔을 때 아래 중 하나라도 해당하면 첫 버전에 넣지 않는다.

1. 매장이 2곳 이상이어야 성립하는 기능
2. 고객이 매장에 오지 않아도 되는 기능
3. 실제 금전 이동이 필요한 기능
4. 상품 수가 수백 개 이상이어야 효용이 생기는 기능

## 가정 / 미확정

### 가정 (확인 필요)

| # | 가정한 내용 | 근거 | 틀릴 경우 영향 |
|---|---|---|---|
| A1 | 대상 고객은 매장을 직접 방문할 수 있는 인근 생활권 소비자다 | 매장 픽업이 유일한 수령 수단이라는 전제 | 대상 사용자 정의와 성공 지표 모수가 바뀐다 |
| A2 | 관리자는 매장 운영자·직원 소수이며 별도 권한 등급을 나누지 않는다 | 단일 매장 전제 | 관리자 요구사항에 권한 등급 체계가 추가된다 |
| A3 | 성공 지표 측정 기간을 공개 후 8주로 잡는다 | 신선식품 판매 주기가 짧아 4주면 계절 변동을 흡수하지 못한다 | 목표치 기준선을 다시 잡아야 한다 |
| A4 | 목표 수치(M1~M9)는 유사 마감 할인 서비스의 통상 범위를 기준으로 한 초기 기준선이다 | 실측 데이터가 없다 | 목표치만 조정하면 되며 기능 범위에는 영향이 없다 |
| A5 | 상품 카테고리는 신선식품으로 한정하고 가공식품·비식품은 다루지 않는다 | 서비스 전제의 "신선식품" 표현 | 상품 속성과 마감 기준 정의가 확장된다 |
| A6 | 고객은 1인 1계정을 사용하며 계정 공유를 가정하지 않는다 | 노쇼 누적 제재를 계정 단위로 적용하기 위함 | 노쇼 제재 기준을 다시 설계해야 한다 |
